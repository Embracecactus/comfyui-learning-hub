# 模型路由与 Token 使用规范

## 目的与适用范围

本规范适用于 ComfyUI 仓库内的分析、实现、审查、验证和协作任务。目标是让模型能力与任务风险匹配，控制上下文规模，并使每个结论都可复核。

## 任务分级与模型路由

先按任务的风险、判断复杂度和读写比例分级；无法确定时按较高等级处理。

| 等级 | 适用任务 | 默认模型与工作方式 |
| --- | --- | --- |
| S0 | 简单问答、单行命令、纯文字改写、无需仓库状态的解释 | 主代理直接完成，不委派子代理。 |
| S1 | 狭窄、重复、可机械验收的清单、格式检查、小范围独立编辑 | `gpt-5.6-luna`，`low` 或 `medium`；限定输入、输出和验收命令。 |
| S2 | 读多写少的代码/日志/配置梳理、证据收集、常规审查 | `gpt-5.6-terra`，`medium`；优先只读探索，返回压缩后的证据。 |
| S3 | 需求澄清、架构决策、复杂根因、安全与兼容性判断、最终验收 | `gpt-5.6-sol`；由主代理保持上下文并作最终决定。 |

模型路由是默认值，不替代主代理的责任。涉及安全、破坏性操作、跨模块边界或无法复现的失败时，必须升级到 S3 复核。

## 30 秒路由判断

按顺序判断，命中后停止：

1. 两次以内的明确检查或极小修改能结束吗？能则按 S0，由主代理直接完成。
2. 输入、输出和验收命令都能提前写清，结果主要是机械变换吗？能则按 S1。
3. 主要成本是阅读大量文件、日志或网页并压缩成证据吗？是则按 S2。
4. 其余涉及取舍、跨层影响、外部状态、安全或最终签收的工作均按 S3。

不要为了“看起来并行”而委派。若主代理说明任务的文字已经接近亲自完成所需的信息量，继续由主代理处理通常更省 Token。

## 委派与编辑边界

- 每项任务最多同时使用两个子代理；子任务必须独立、边界清楚，禁止并行处理有依赖关系的工作。
- 同一文件在同一时段只能有一个编辑者。委派读操作或机械产出时，先明确文件范围；主代理负责合并、冲突判断和最终验收。
- 子代理不得扩大文件范围、改变需求或执行未授权的外部写入。未明确授权时，不执行 git 操作、远程操作或删除/覆盖性操作。
- 需要跨文件设计、接口取舍、复杂调试或安全判断时，不将决策拆给低等级模型；升级 S3。

## 上下文与 Token 控制

- 先读取项目指令、相关配置和最小必要代码；使用精确搜索与指定行段，避免无关全量文件、重复日志和整仓库上下文。
- 每次委派只传任务目标、范围、已知约束和验收标准；不要转发主对话中的无关历史。
- S1/S2 默认使用无历史或最少历史分叉，由主代理提供一份自包含任务胶囊；只有任务确实依赖对话决策时才附带最近必要回合。
- 同一领域的追问优先复用已有子代理线程，避免新代理重复读取相同文件。
- 先复用已有结论和证据；对失败命令保留关键错误、命令和环境，不重复粘贴完整输出。
- 子代理回报目标控制在约 15 行；长日志、完整 JSON 和大段源码留在文件中，只回传精确路径、行号和关键片段。
- 发现任务范围扩大、证据互相矛盾、机械规则无法覆盖，或低等级模型连续一次无法给出可验证结果时，立即升级一级；达到架构/安全/最终验收性质时直接升级 S3。
- 主代理在交付前检查：是否回答了原需求、是否越过文件/权限边界、是否存在未验证推断，以及验证范围是否被准确表述。

## 子代理返回模板

所有子代理必须按以下结构返回，尽量短且指向精确文件、行号、符号或命令：

```text
结论：一句话说明结果、是否完成及不确定项。
证据：列出实际检查的文件/行号/符号、命令及关键输出；区分事实与推断。
风险：列出剩余风险、未覆盖范围和是否需要升级。
验证：列出已执行的验证、结果和准确边界；未执行则明确写“未执行”。
```

没有足够证据时必须写明“未确认”，不得用通过构建、静态检查或单元测试代替硬件、生产或远程验收证明。

## 当前 ComfyUI 示例

- S0：解释一个现有节点参数的含义，且不需要读取仓库。
- S1：统计指定目录中的节点文件，检查命名格式，或对单个文档执行 Markdown 链接检查；交给 `gpt-5.6-luna low/medium`，输出清单和可重复命令。
- S2：梳理某个自定义节点从注册到执行的调用路径，或分析启动日志中的模型加载失败；交给 `gpt-5.6-terra medium`，只读收集文件/行号和最小证据。
- S3：决定节点 API 兼容性改造方案、判断模型加载崩溃的跨层根因、评估安全影响，或进行合并前最终验收；由 `gpt-5.6-sol` 结合完整约束作决定。

若 S1 的格式检查发现规范冲突，或 S2 的调用路径涉及架构改动，应停止原路由并升级 S3；修改同一文档或代码文件时由指定的单一编辑者完成。
