## 1. 直接回答(完整价格结论)

### 768P 视频(从提示词到成片)

**RunningHub 平台上,唯一提供 768P 档的视频模型是 MiniMax H3 家族**
(7 个端点:`hailuo-h3` 文生/图生/多模态 + `hailuo-h3-max` 文生/图生 +
`h3-max-turbo` 文生/图生)。其余 221 个视频模型最高只有 720p/1080p/2k/4k,
**没有 768P 标签档**。

**路线一(实测,2026-09-16):平台工作流托管开源 H3 权重**——
`examples/workflows/h3-t2v-open-768p-cloud.json`(fl2va int8 + 8 步
turbo LoRA + `MiniMaxH3ImageToVideo` 纯文生视频,ResolutionSelector
megapixels=0.98@16:9 = 1344×768)。经对外客户端执行,个人 Key 可用:

| 项 | 实测值 |
| --- | --- |
| taskId | `2100021717924806657` |
| 输出 | 1344×768@24fps、5.167s、h264+AAC 带原生音轨(sha256 `f5176d6b99d9…`) |
| 费用 | **78 RH 币 / 195 运行秒(含冷启动)**;无第三方费;0.4 币/秒(plus 48G 档) |
| 每成片秒 | 78 币 ÷ 5.167 成片秒 ≈ **15.1 币/成片秒**(币→元官方比例未定,保留原单位) |
| 10/15 秒 | 线性推算 156 / 234 币,未实测;实例热时单条更低 |

**路线二(推算):标准模型 API 直调** —— 仅企业级-共享 Key(个人 1014,
09-07/12/13 三次):

| 时长 | 完整生成总价(推算) | 每成片秒 | 口径 |
| --- | --- | --- | --- |
| 5 秒 | **≈¥2.50** + 平台币(渠道而定) | ¥0.50 | MiniMax 原厂参考价(非平台报价) |
| 10 秒 | ≈¥5.00 + 币 | ¥0.50 | 同上 |
| 15 秒 | ≈¥7.50 + 币 | ¥0.50 | 同上 |

两条路线**不可直接比价**:路线一按运行秒计币(分辨率由工作流参数控制,
同一工作流改 megapixels 即可出其他分辨率,单价随运行时长变化);路线二
按成片秒计人民币(分辨率是模型档位)。

**为什么是"推算"而非"标价/实测"**:RunningHub 的标准模型 API 定价文件
(官方 developer-kit,353 条,2026-04-29 快照)中 **H3 全家族零条目**;
`price-preview` 接口只有企业级-共享 Key 能调(个人 Key 实测 1014,
2026-09-07/09-12/09-13 三次)。因此平台侧官方价**当前无法核验**,表中数字
按 **MiniMax 原厂参考价(H3 768P = ¥0.50/秒)换算——原厂参考价不是
RunningHub 平台报价,也不能未经证明当作平台价格下界**(平台可能加价、
打折或改计费单位)。实测旁证仅有一例:2K 档第三方费实测 ¥0.77/秒,
与原厂 2K 参考价 ¥0.80/秒差 3.7%,方向上接近但不构成 768P 的外推依据
(规则:不用一条 2K 样本的折扣比例推断 768P 价格)。

**2K 结论**:
1. **从头生成一条 2K 视频,最便宜且已实测的路线是 AI 应用直出 H3 2K:
   5 秒 = 第三方费 ¥3.85 + 平台 7 币**(币→元比例未定,见 §5);
   第三方费部分每成片秒 ¥0.77。
2. **2K 不是"必须先 768P 再升级"**:H3 的 2K 是单个任务的单一报价;
   实测任务的完整费用链(parent + child usage)中不存在独立的 768P
   任务扣费。原厂按秒计费模型($0.13/s ≈ ¥0.80/s)本身已含其内部阶段,
   **不得再叠加一次 768P 生成费或高清化费**。
3. 官方确实**也提供**两阶段路线(情形 C,`regeneration-*-to-video`
   三个端点),但按原厂参考价合计 ¥1.10/秒,比直出 2K 贵约 37%——
   仅在需要保留 768P 中间产物时才有意义。
4. 任务失败/取消:任务未起跑(参数校验失败、414 余额/算力闸门、
   1014 渠道拒绝)不产生费用(实测 414/1014 均零扣费);已运行任务
   按规则计费,失败任务在工作流路线上**仍计运行时长**(平台规则,
   doc14/16 记录)。MiniMax 原厂政策"失败或触发安全审查不扣费"仅约束
   原厂侧,不自动等于 RunningHub 平台侧退款政策(**未确认**)。

## 5. 无法确认的费用与缺口

1. **H3 的 RunningHub 平台侧官方价**(768P/2K/regeneration 全部):
   定价文件无条目 + price-preview 需企业 Key。缺的证据:一次企业 Key 的
   `price-preview` 返回,或一条标准模型 API 实跑账单。
2. **平台币→人民币官方兑换比例**:影响"7 币"折多少钱。
   缺的证据:控制台「任务与账单」对账截图/明细。
3. **AI 应用的计费公式**(7 币是按次还是按什么计):未公开。
4. **10 秒/15 秒的实测价**:按官方每秒计费规则线性推算,未实测。
5. **768P 档实际输出像素**:推断 16:9 下 1344×768(依据 regeneration
   接口对源视频的约束:尺寸被 32 整除、面积上限 768×1344);未实测。
6. **失败/取消/超时的退款规则**(平台侧):未在公开文档找到明确条款。
7. **seedance-2.5-token、h3-max-turbo、wan-3.0、gemini-omni-1.1 等
   新端点价格**:官方定价文件未收录。

以上缺口都不阻塞已有结论:已实测的 2K 链路与原厂锚点推算的 768P 链路
足以回答"从头生成各要多少钱"的主问题,缺口只在精度(±平台加价/币值)。
