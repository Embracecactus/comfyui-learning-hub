# 单提示词接入、只读取证与两阶段对账

维护日期：2026-09-21。本次修复不充值、不变更会员或 Key 权益、不创建付费任务。所有测试使用合成响应，不替代企业和两阶段的真实账单。

## 1. 一个提示词，明确选择通道

从仓库根目录运行；Python 3.10+，仅标准库。视频下载后的媒体检查需要 PATH 中有 ffprobe。

```bash
CLIENT=docs/05-RunningHub-API/examples/python/rh_min_client.py
AUDIT=docs/05-RunningHub-API/examples/python/rh_evidence_audit.py
# 无Key、无网络、无扣费的个人应用计划
python3 "$CLIENT" video --key-type consumer-member --prompt '一只橙猫在雨后屋顶缓慢行走' --resolution 2K --duration 5
# 企业共享计划：同一个提示词，直接调用标准模型API
python3 "$CLIENT" video --key-type enterprise-shared --prompt '一只橙猫在雨后屋顶缓慢行走' --resolution 2K --duration 5
```

`--duration` 必须是5至15的整数，发送为字符串；消费者渠道默认使用历史验证的应用 `2083105376052006914`，节点1的 prompt/resolution/duration/ratio。其他应用需先读取自己的参数契约，不能盲套节点编号。个人/团队是结算主体，消费级/共享/独占是 Key 类型；独占 Key 不能直接调标准模型端点。

只在本机安全环境中配置 `RH_API_KEY`，不要把 Key 放在源码、对话、命令历史或共享日志。**只有显式增加 `--execute` 才会创建任务。** 标准模型执行前免费预估，失败默认中止；`--allow-unpriced` 是独立接受未知费用的开关，不作为日常默认。个人应用的附加 RH 币不能用标准模型预估代替。

本目录 `examples/curl/*.sh` 保留原入口名，但生命周期委托 Python 客户端，避免五套不同的重试、taskId保存和轮询逻辑；均默认 dry-run。直接 HTTP 的两个响应契约如下。

## 2. 修正后的 HTTP 契约

标准模型 POST `/openapi/v2/minimax/hailuo-h3/text-to-video` 通常返回顶层 `taskId`、`status`、`errorCode`、`errorMessage`；旧 `/task/openapi/ai-app/run` 与 `/task/openapi/create` 通常返回 `code=0` 和 `data.taskId`。客户端检查两层业务错误，不把 HTTP 200 当作业务成功。

账户状态：POST `/uc/openapi/accountStatus`；Header Bearer 和 body 的小写 `apikey`。它不是完整账单接口。应用提交 body 使用 `apiKey`，大小写不同。

价格预估：POST `/openapi/v2/price-preview/{endpoint}`，payload与目标生成完全一致。返回 `estimatedPrice`、`currency` 等；保留平台单位，不把1014或空字段视为零元。

```bash
python3 "$CLIENT" account
python3 "$CLIENT" price minimax/hailuo-h3/text-to-video '{"prompt":"橙猫走过雨后屋顶","resolution":"2K","duration":"5","ratio":"16:9"}'
# 已经返回taskId后，超时、断网或下载失败都只续查，不重新生成
python3 "$CLIENT" resume '<已有taskId>'
```

生成请求只发送一次。失去响应、非JSON或响应无taskId均保留 `SUBMISSION_UNCERTAIN`；先核对控制台，不能因本地报错推断“没有创建任务”。明确业务拒绝才是 `SUBMIT_REJECTED`。本地轮询超时不取消服务器任务。下载或 ffprobe 失败不会标为 `MEDIA_VALIDATED`。

## 3. 企业价格与历史任务的只读采集

```bash
python3 "$AUDIT" collect --plan docs/05-RunningHub-API/examples/enterprise-price-plan.json \
  --task-id 2098737586251202562 --task-id 2100124158796193794 \
  --task-id 2100427462658981891 --out output/runninghub/api/evidence/readonly.json
```

该工具只查询现有taskId与price-preview，**没有生成接口**。缺Key退出2并保存 `blocked_missing_key`，不发送请求；无权限或查询失败也保存具体阻塞。任务ID去重，报价与账单分别存储。示例计划覆盖H3文生768P/2K的5/10/15秒；不是每个模型都套这个参数范围。

导出摘录会删除Key、私有余额和媒体签名URL，提示词只留哈希；私人完整原文仍应留在本机忽略目录。不要把历史HTML中三次成功摘要称为本轮重新实测。只读报价成功也不是扣费验证成功。平台可能不允许当前Key查看历史任务，此时保留错误而不是编造成功。

## 4. 768P→regeneration 2K：不能跳过的源链校验

标准文生再生成契约是 [官方 text regeneration 文档](https://www.runninghub.cn/runninghub-api-doc-cn/api-498427811)，而非image regeneration页面。源应为包含音轨的24fps MP4，宽高可被32整除、面积不超过768×1344、107至362帧。请求字段为 `prompt`、`baseVideoUrl`、`resolution="2K"`。

**prompt必须是源任务实际送入模型的最终提示词**，不是可能被扩写前的原始用户提示词。没有最终提示词证据就阻塞；不得自行补一句“看起来相同”。云端开源工作流768P成功也不自动证明其产物被标准regeneration接受。

本机 `source-record.json` 至少包含 `task_id`、精确源 `endpoint`、成功 `status`、从源任务取得的 `final_model_prompt`。把相同文本原样写入 `final-prompt.txt`，不要自动追加换行。两个文件均留在 output 下。

```bash
python3 "$AUDIT" source-check --video output/source.mp4 \
  --source-record output/source-record.json --final-prompt-file output/final-prompt.txt \
  --out output/source-check.json
# 默认仅校验及打印再生成计划，不上传、不生成
bash docs/05-RunningHub-API/examples/curl/03-h3-regen-768p-to-2k.sh \
  output/source.mp4 output/source-record.json output/final-prompt.txt
```

本地检查不证明服务器接受该视频。再生成示例只有追加 `--execute` 才上传并预估；取得有效预估后才提交一次。调用者须先取得费用授权。真实再生成响应、源上传关联及最终提示词需要留存，后续对账才能证明属于同一条链。不要用占位URL调用报价，更不能用上游MiniMax价格填RunningHub账单空缺。

## 5. 双任务成本对账输入

两个阶段各提供一个本机JSON账单摘要：`task_id`、`endpoint`、`status="SUCCESS"`、`final_prompt_sha256`、`billing_complete`、`cost_components`。阶段A另有实际文件 `output_sha256`；阶段B另有 `source_task_id` 和 `source_sha256`，必须与A对应。`billing_complete=true`只能在所有独立收费项均已核对后填写，不能为通过校验而设置。

每个 `cost_components` 条目包含：`charge_id`（平台账单行ID或由已识别task/字段范围组成的稳定唯一ID）、`scope="disjoint_charge"`、`source_field`、`unit`（`CNY`或`RH_coin`）、`amount`（精确十进制字符串）。必须有响应/账单来源证明各项互不重叠。`parent total`、`child total`或 `query`/`outputs`中的重复汇总，不能当成新的独立费用。

```bash
python3 "$AUDIT" reconcile --stage-a output/stage-a.json --stage-b output/stage-b.json \
  --out output/two-stage-cost.json
```

相同charge_id只计一次；同ID金额冲突、未知scope、缺项、空金额或链路不匹配则保持 `incomplete`。CNY与RH币分别相加；币兑人民币未知时不生成全人民币总价。这个结果仅证明提供的账单范围与算术自洽，不是对真实账单来源的第三方认证。失败、退款、重试、会员/租金摊销应另列，不能混入两个成功任务而丢失来源。

## 6. 维护与放行

只在 `data/handoff-evidence.json` 修改精确端点的价格、已验证样本、权益或缺口；保留时间、单位、来源和证据等级。运行统一生成器后执行回归和 `--check`。CSV采用新的英文机器字段，旧中文列名消费者需升级；CLI旧命令保留，并新增 `account` 与 `video`。

当前可关闭：文档/CSV/HTML一致性、响应解析、账户命令、单提示词入口、提交安全、快照来源与纳入规则。当前不可自动关闭：企业真实账单、两阶段真实总价、RH币兑换、独占租金、长时长个人附加币和最新目录/定价。它们在数据中有独立缺口及关闭证据要求，不再混用“全完成”。
