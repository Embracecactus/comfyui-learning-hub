# RunningHub 视频换装 V2：小白首跑指南

> **2026-09-02 实跑结论：失败，停止用于平铺商品图换装。** RunningHub 任务 `2095068054227742722` 用黑色 `1977` 平铺卫衣实跑约 `07:19`，最终人物仍是黑色内衣式上装和长裙；卫衣的帽子、长袖、宽松版型与 `1977` 均未出现。本文件保留为失败实验和遮罩排错资料，不要继续用它消耗积分。下一次请改用[RunningHub H3 卫衣等条件复跑](13-RunningHub-H3卫衣等条件复跑.md)。

这版原本想解决上一版 MiniMax H3 平台移植没有换上商品的问题，但实际选错了模型条件语义。视频能生成、原衣服能被遮罩，不等于目标商品已经取得控制权。

本工作流的验收标准只有一句话：

> 上传的商品服装必须出现在人物身上；如果人物仍穿参考视频里的原衣服，就判失败。

## 1. 下载与导入

下载并导入下面这个文件：

[`workflows/rh-video-tryon-v2.json`](workflows/rh-video-tryon-v2.json)

文件名只有 22 个字符，没有超过 RunningHub 的 50 字限制。

导入后出现“图片未选择”或“视频未选择”是正常现象。为了防止误用公开案例或其他账号的素材，工作流故意清空了两个媒体输入。

## 2. 原设计思路，以及为什么没有成功

核心数据流如下：

```text
商品服装图
  → 调整尺寸
  → CLIP Vision 提取服装颜色、图案、材质和版型
  ───────────────────────────────┐
                                  ↓
参考视频 → 取首帧 → 找出原服装 → 全视频追踪服装遮罩
    │                              │
    └→ 擦除每一帧的原服装区域 ──────┼→ Wan 2.2 Animate 重绘 → 最终视频
                                   │
                   原动作、镜头、人物和背景继续保留
```

原设计做了两个隔离规则：

- 商品图只进入 `WanVideoClipVisionEncode` 的服装身份分支。
- 参考视频不会进入服装视觉编码；它只提供待擦除区域、逐帧动作、镜头、人物和背景。

这与上一版“整段参考视频同时影响动作和衣服外观”不同，但隔离输入并没有补上真正的“平铺服装 → 人体穿着关系”。

Wan Animate 官方定义的是人物动画与人物替换；它的参考图应是目标人物/角色图，而不是单独平铺的一件衣服。当前图把平铺卫衣同时交给 `WanVideoClipVisionEncode` 和 `WanVideoAnimateEmbeds.ref_images`，但整条图里没有虚拟试衣、服装人体解析、纹理贴附或 Logo 保真模块。模型只读到了“黑色服装”的弱外观线索，于是在被擦除区域自行补成黑色内搭和裙装。

因此，继续放大遮罩、增加步数或改几句提示词都不能补出缺失的服装上身机制。若仍要使用 Wan Animate，必须先用静态虚拟试衣模型得到“人物已经穿好目标卫衣”的完整参考人物图，再把该人物图送入 Wan Animate；平铺卫衣不能直接作为角色参考图。

## 3. 第一次运行只做两次上传

### 3.1 上传商品服装图

找到绿色节点：

```text
① 上传商品服装图｜服装身份唯一来源
```

建议图片满足以下条件：

- 一张图中只有一件主要服装。
- 正面、清晰、无强反光和严重褶皱。
- 白底、透明底或简单背景均可。
- Logo、文字和花纹尽量占有足够像素。
- 首次仍使用已经对比过的黑色 `1977` 卫衣，方便判断是否真的替换。

### 3.2 上传动作参考视频

找到紫色节点：

```text
② 上传参考视频｜提供人物动作镜头场景，不进服装编码
```

首次请选择：

- 单人、竖屏、全身或大半身视频。
- 人物不要频繁出画。
- 手臂不要长时间挡住衣服。
- 原服装与背景颜色有明显区别。
- 先使用约 3～5 秒的视频，不要直接上传 20 秒成片。

工作流已经限制为：

| 参数 | 首跑值 | 作用 |
| --- | ---: | --- |
| 宽度 | `432` | 低成本验证服装替换 |
| 高度 | `768` | 9:16 竖屏，且宽高均是 16 的倍数 |
| 帧率 | `10 FPS` | 降低首跑计算量 |
| 最大帧数 | `49` | 最多约 4.9 秒 |
| 采样步数 | `4` | 使用公开工作流的快速 LoRA 组合 |
| 种子策略 | `fixed` | 修改一个参数后可以公平对比 |

## 4. 最重要的一步：选择原视频服装区域

找到节点：

```text
⑥ 原视频服装区域｜默认抹掉全部衣服类别
```

这里的选择依据是**参考视频人物原来穿什么**，不是商品图是什么。

例如，参考视频里的人穿黑色花裙，商品图是卫衣，也必须勾选 `Dress`，否则花裙不会被擦除。

首跑默认勾选以下五项：

- `Upper-clothes`
- `Skirt`
- `Dress`
- `Belt`
- `Pants`

为了让本次“无袖花裙 → 长袖 `1977` 卫衣”的验收成立，首跑还默认勾选 `Left-arm` 和 `Right-arm`，允许模型在裸露手臂区域生成长袖。脸、头发、腿、鞋、包和背景仍不勾选。

服装类别依据原视频人物原来穿什么；双臂是否勾选则依据目标商品的袖长：

- 长袖商品替换无袖或短袖原服装：先勾选双臂。
- 目标也是无袖或短袖：关闭双臂可减少手臂和手部重绘。

首跑成功后，为了少改动人物，可以按原视频服装缩小范围：

| 原视频中的衣服 | 建议勾选 |
| --- | --- |
| T 恤、衬衫、卫衣、外套 | 只选 `Upper-clothes` |
| 连衣裙 | 只选 `Dress` |
| 半身裙 | 只选 `Skirt` |
| 长裤、短裤 | 只选 `Pants` |
| 上下装都要替换 | `Upper-clothes` + `Skirt` 或 `Pants` |

不要随意勾选 `Face`、`Hair` 或 `Background`，否则可能把换装变成人脸重绘或整幅画面重绘。双臂包含皮肤区域，开启后也要重点检查手部是否变形。

## 5. 运行后按三个画面检查

点击运行。不要只看最终视频，依次检查下面三项。

### 5.1 红色动态遮罩

找到：

```text
遮罩预览｜红色必须覆盖原视频服装
```

合格表现：

- 红色区域从第一帧到最后一帧都跟着衣服移动。
- 原衣服主体被完整覆盖。
- 脸、头发、背景和大面积皮肤没有变红。

红色遮罩漏掉原衣服时，最终视频一定容易残留原服装。

### 5.2 擦除预览

找到：

```text
擦除预览｜原服装区域必须变黑
```

合格表现：原服装区域已经变成连续的黑色空洞，人物动作、未遮挡身体、镜头和背景仍与原视频同步。

### 5.3 最终视频

找到绿色节点：

```text
⑫ 最终视频｜必须看到商品服装发生替换
```

用下面这张表验收：

| 检查项 | 通过 | 不通过 |
| --- | --- | --- |
| 商品身份 | 能认出商品图的主色、版型和主要图案 | 还是原视频衣服 |
| 原服装清除 | 原裙子、上衣或裤子不再出现 | 原服装边缘、花纹持续残留 |
| 动作 | 与参考视频主要动作和节奏一致 | 人物动作被静态商品图锁死 |
| 背景与镜头 | 大体保持原视频 | 背景被大面积重新生成 |
| 时序 | 衣服随身体连续运动 | 每帧颜色跳变、Logo 四处漂移 |

只要“原衣服还在”，就先修遮罩，不要先加采样步数或提高分辨率。

## 6. 常见问题怎么改

### 原视频衣服仍然露出来

1. 回到节点 ⑥，确认选中了原视频衣服对应的类别。
2. 把 `GrowMask` 的 `expand` 从 `10` 调到 `16`。
3. 仍有窄边残留时再试 `24`，不要一次调得过大。

遮罩过大会吞掉手、脖子或背景；出现这种情况就往回减。

### 商品颜色对了，但 Logo 或文字不稳定

- 换用更清晰、更正面的商品图。
- 先保持 4 步和固定种子，不要同时改多个参数。
- 确认低分辨率功能通过后，再提高到 480×848 或 576×1024。
- 生成模型会重新绘制服装，不能保证像素级复制小字；严格 Logo 保真通常还需要后处理跟踪与贴图。

### 人脸、手或身体也被改坏

- 缩小节点 ⑥ 的勾选范围。
- 减小 `GrowMask`。
- 选择遮挡较少的参考视频。
- 不要勾选 `Face`、`Hair`、`Left-arm`、`Right-arm`，除非你明确知道为什么需要它们。

### 动态遮罩中途丢失

- 换成第一帧就能清楚看到衣服的视频。
- 减少快速转身、人物出画和多人交叉。
- 先截取一个连续的 3 秒片段验证。
- 必要时调整 `PrimitiveInt（起始追踪帧）`，使起始帧落在衣服最清楚的位置。

## 7. 通过后再提高画质

按下面顺序一次只改一项：

| 阶段 | 分辨率 | FPS | 帧数 | 目的 |
| --- | --- | ---: | ---: | --- |
| A 功能验证 | 432×768 | 10 | 49 | 确认真的换衣服 |
| B 细节验证 | 480×848 | 10 | 49 | 检查衣服纹理与边缘 |
| C 时序验证 | 480×848 | 15 | 73 | 检查动作和闪烁 |
| D 交付候选 | 576×1024 | 15 | 按片段决定 | 前三项稳定后再增加成本 |

宽和高必须是 16 的倍数。分辨率、FPS 和帧数同时提高会成倍增加时间与费用，因此不要一步跳到最高档。

## 8. 关键节点到底做什么

| 节点 | 小白解释 |
| --- | --- |
| `VHS_LoadVideo` | 把 MP4 拆成连续图片，并保留音频和帧率信息。 |
| `ImageFromBatch` | 从视频帧中取一张起始帧，用来识别原服装。 |
| `ClothesSegment` | 按上衣、裙子、裤子等人体解析类别生成首帧服装遮罩。 |
| `SeCModelLoader` | 加载视频目标跟踪分割模型。 |
| `SeCVideoSegmentation` | 把首帧服装遮罩沿人物动作传播到后续每一帧。 |
| `GrowMask` | 稍微向外扩展遮罩，减少衣服边缘残留。 |
| `BlockifyMask` | 把遮罩整理成更适合 Wan 视频重绘的块状边界。 |
| `DrawMaskOnImage` | 一条链显示红色遮罩，另一条链把原衣服区域擦成黑色。 |
| `LoadImage` | 读取商品服装图，是目标服装身份的唯一素材输入。 |
| `ImageResizeKJv2` | 把商品图适配到视频画布，同时保持比例并补边。 |
| `CLIPVisionLoader` | 加载视觉特征模型。 |
| `WanVideoClipVisionEncode` | 把商品图编码成 Wan 能理解的服装外观特征。 |
| `WanVideoModelLoader` | 加载 Wan 2.2 Animate 14B FP8 视频模型。 |
| `WanVideoLoraSelectMulti` | 加载加速、补光和视频重绘相关 LoRA。 |
| `WanVideoSetBlockSwap` | 在云端显存紧张时分块换入换出模型。 |
| `WanVideoTextEncodeCached` | 编码正向和负向提示词。 |
| `WanVideoAnimateEmbeds` | 合并商品特征、擦除后的视频、遮罩、尺寸和帧数。 |
| `WanVideoSampler` | 执行 4 步扩散采样，真正生成新的视频潜变量。 |
| `WanVideoDecode` | 把潜变量还原成可见的视频帧。 |
| `VHS_VideoCombine` | 把图片序列和原视频音频封装成 MP4。 |

## 9. 来源、留痕与验证边界

本文件基于 RunningHub 公开可下载的[“视频换装”工作流](https://www.runninghub.cn/post/2025934636399988738)做教学化改造。公开说明建议视频不超过 20 秒，显存不足时降低宽、高和帧率；本项目进一步把首次测试限制到 49 帧，避免一上来浪费运行费用。

工作流中的 `VHS_LoadVideo` 固定对应 VideoHelperSuite 版本 `8e4d794...`。该版本源码会忽略已经废弃的 `force_size` 隐藏字段，并在 `custom_width` 或 `custom_height` 非零时直接执行缩放；因此 JSON 中保留 `force_size: Disabled`，同时由节点 ③、④把实际尺寸连接为 432×768。这不是“未开启缩放”。可在[该版本的官方源码](https://github.com/Kosinkadink/ComfyUI-VideoHelperSuite/blob/8e4d79471bf1952154768e8435a9300077b534fa/videohelpersuite/load_video_nodes.py#L274-L307)核对。

公开源工作流于 2026-09-02 下载，SHA-256：

```text
81308448f84f78327032ad700e37d6953828b6d8c8e02123ca2dc0b22bf5da3b
```

确定性改造脚本：

```bash
node scripts/derive_rh_video_tryon_v2.mjs
```

本地自动检查只能证明：JSON 结构有效、两类输入在拓扑中隔离、媒体输入已清空、连线一致。它不能证明模型理解了平铺服装，也不能代替视觉验收。本次平台实跑已经否定了这条路线的商品换装功能。

两个失败文件都保留，不再推荐运行：

- [`yinghai-h3-runninghub-0.2mp.json`](workflows/yinghai-h3-runninghub-0.2mp.json)：H3 平台移植时错误改成了通用提示词和参考视频前半段。
- [`rh-video-tryon-v2.json`](workflows/rh-video-tryon-v2.json)：Wan Animate 收到的是平铺服装，而它需要完整角色参考图。
