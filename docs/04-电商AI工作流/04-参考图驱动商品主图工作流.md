# 04｜参考图驱动商品主图：FLUX.2 Klein 双参考编辑

第 3 阶段已经证明透明商品、遮罩、批次和原像素合成链路可以正常运行，但它只能套固定背景。根据[映海站实测记录](reference-site-audit-2026-08-28.md)，真正的“复刻商品主图”至少需要同时理解：

1. 自家商品是什么，哪些结构和材质必须保留。
2. 对标图的构图、光线、色彩和视觉层级是什么。
3. 最终图片要表达什么商品卖点。

本章使用 ComfyUI 官方支持的 **FLUX.2 Klein 4B Distilled 图像编辑模型**，搭建最小的双参考链路：

```text
自家商品图（图 1，身份参考） ─┐
                               ├→ 两张图编码为 ReferenceLatent
对标主图（图 2，视觉参考） ───┘                 │
                                                  ├→ FLUX.2 Klein 4 步采样 → 完整成片
商品保真与复刻规则提示词 ─→ CLIPTextEncode ─────┘
```

## 1. 与第 3 阶段的本质区别

| 第 3 阶段 | 本章 |
|---|---|
| SDXL 只生成背景 | FLUX.2 Klein 重绘整张商品主图 |
| 商品 PNG 最后覆盖 | 商品图作为语义与外观参考参与采样 |
| 四套固定提示词 | 由任意一张对标主图提供视觉条件 |
| 光影容易不一致 | 商品、阴影、反射、背景共同生成 |
| 商品像素最稳定 | 构图和融合更自然，但包装细节可能漂移 |

这不是简单升级替换。两条路线以后都保留：

- 包装文字、Logo、SKU 必须像素级不变：优先第 3 阶段原像素合成。
- 更看重整体构图、真实环境融合和对标图风格：使用本章语义编辑，并人工复核商品细节。

## 2. 工作流来源和修改记录

本章 JSON 不是凭空猜节点，而是派生自 ComfyUI 官方模板：

```text
Comfy-Org/workflow_templates
templates/image_flux2_klein_image_edit_4b_distilled.json
```

本项目只做了这些可追踪修改：

1. 保留官方“双图参考”子图，关闭无关的单图改色示例。
2. 将图 1 定义为自家商品身份，将图 2 定义为对标视觉参考。
3. 把提示词改为“保留商品、借鉴构图、禁止复制竞品品牌和文字”。
4. 输出前缀改为 `ecommerce/reference-main-image-flux2-klein`。
5. 考虑 8 GB 显存，把官方 `1024 × 1024 / 1 MP` 起点下调为 `768 × 768 / 0.6 MP`。

JSON 中的 `extra.audit` 保存了来源 URL、日期、派生脚本和修改摘要。重新派生命令见[实测记录第 8 节](reference-site-audit-2026-08-28.md#8-官方来源与可复现文件)。

## 3. 模型准备

需要三个文件：

| 文件 | 正确字节数 | 目录 | 用途 |
|---|---:|---|---|
| `flux-2-klein-4b-fp8.safetensors` | `4,070,624,520` | `models/diffusion_models` | 4B 蒸馏图像编辑模型 |
| `qwen_3_4b.safetensors` | `8,044,982,048` | `models/text_encoders` | 理解商品描述、编辑规则和参考图语义 |
| `flux2-vae.safetensors` | `336,213,556` | `models/vae` | 商品图、参考图和结果在像素/潜空间间转换 |

ComfyUI Desktop 共享模型根目录：

```text
%LOCALAPPDATA%\Comfy-Desktop\ComfyUI-Shared\models
```

### 3.1 国内镜像断点续传命令

在 Windows CMD 运行：

```bat
set "MODEL_ROOT=%LOCALAPPDATA%\Comfy-Desktop\ComfyUI-Shared\models"

cd /d "%MODEL_ROOT%\diffusion_models"
curl.exe -L --fail --retry 20 --retry-all-errors --retry-delay 5 -C - -o "flux-2-klein-4b-fp8.safetensors.download" "https://hf-mirror.com/black-forest-labs/FLUX.2-klein-4b-fp8/resolve/main/flux-2-klein-4b-fp8.safetensors"

cd /d "%MODEL_ROOT%\text_encoders"
curl.exe -L --fail --retry 20 --retry-all-errors --retry-delay 5 -C - -o "qwen_3_4b.safetensors.download" "https://hf-mirror.com/Comfy-Org/z_image_turbo/resolve/main/split_files/text_encoders/qwen_3_4b.safetensors"

cd /d "%MODEL_ROOT%\vae"
curl.exe -L --fail --retry 20 --retry-all-errors --retry-delay 5 -C - -o "flux2-vae.safetensors.download" "https://hf-mirror.com/Comfy-Org/flux2-dev/resolve/main/split_files/vae/flux2-vae.safetensors"
```

下载完成后先检查文件不再增长、不是几百字节的错误页，再分别改名：

```bat
move /Y "%MODEL_ROOT%\diffusion_models\flux-2-klein-4b-fp8.safetensors.download" "%MODEL_ROOT%\diffusion_models\flux-2-klein-4b-fp8.safetensors"
move /Y "%MODEL_ROOT%\text_encoders\qwen_3_4b.safetensors.download" "%MODEL_ROOT%\text_encoders\qwen_3_4b.safetensors"
move /Y "%MODEL_ROOT%\vae\flux2-vae.safetensors.download" "%MODEL_ROOT%\vae\flux2-vae.safetensors"
```

CMD 中检查单个文件的精确字节数：

```bat
for %F in ("文件名.safetensors.download") do @echo %~zF
```

必须与上表一致后再去掉 `.download`；下载中断时重复同一条 `curl -C -` 命令即可续传。

`hf-mirror.com` 是社区镜像。模型名称、许可证和官方来源以[ComfyUI 官方指南](https://docs.comfy.org/tutorials/flux/flux-2-klein)及其链接的模型仓库为准。

## 4. 版本和硬件要求

这条官方模板依赖较新的 Core 节点：

```text
EmptyFlux2LatentImage
Flux2Scheduler
ReferenceLatent
GetImageSize
SamplerCustomAdvanced
```

导入后显示这些节点缺失时：

1. 先更新 ComfyUI 实例。
2. Desktop 稳定版仍未包含时，等待 Desktop 稳定版同步或另建 Nightly 实例。
3. 不要在 Manager 中安装同名第三方节点来“补齐”。

官方指南给出的 4B Distilled 参考峰值是约 `8.4 GB VRAM`。不同配置建议：

| 显存 | 起步设置 | 预期 |
|---:|---|---|
| 8 GB | 本章 `768 × 768`、参考图 `0.6 MP`、batch 1 | 需要模型卸载，速度取决于内存和磁盘；先关闭浏览器硬件加速等占显存程序 |
| 12 GB | 可尝试 `1024 × 1024`、参考图 `1 MP` | 更接近官方模板默认值 |
| 16 GB 及以上 | 1024 起步，再按需求测试更大画幅 | 调试余量更充足 |

8 GB 不是“保证不溢出”，而是可尝试的低显存路径。如果系统内存不足或模型卸载失败，仍可能 OOM。

## 5. 画布上看到的 5 个顶层节点

### 5.1 `MarkdownNote`：模型、来源与检查清单

只保存说明，不参与计算。它让工作流单独被复制到别处时仍能找到模型目录、官方来源和本文档。

### 5.2 `LoadImage`：图 1，自家商品身份

输入自己的商品图。第一轮建议：

- 使用正面或 45° 的清晰单商品照片。
- 商品占画面 50%～80%，不要太小。
- 包装文字尽量清晰；过小文字更容易漂移。
- 透明 PNG 或干净白底图都能测试，但不要带多个不同 SKU。

图 1 的职责是回答“最终画面里必须是哪一个商品”。

### 5.3 `LoadImage`：图 2，对标视觉参考

输入想借鉴的竞品主图。它负责：

- 商品在画面中的比例和位置。
- 背景颜色、材质、道具密度。
- 相机角度、光线方向和商业氛围。
- 版式层级，但不应复制竞品品牌、Logo 和文字。

第一轮只用一张构图明确的对标图。多张参考方向冲突时，模型会折中，反而难判断问题来源。

### 5.4 双参考编辑子图

这是计算主体。顶层把复杂内部连线折叠成一个子图，暴露：

```text
模型文件
文本编码器
VAE
编辑提示词
图 1
图 2
seed
```

如果需要看内部节点，可以打开/展开子图；不要把它误认为一个需要 Manager 安装的自定义节点。

### 5.5 `SaveImage`

保存结果到：

```text
ComfyUI/output/ecommerce/reference-main-image-flux2-klein
```

ComfyUI Desktop 通常会把输出根目录重定向到共享目录。目标机器日志中的实际路径是：

```text
%LOCALAPPDATA%\Comfy-Desktop\ComfyUI-Shared\output\ecommerce\reference-main-image-flux2-klein
```

## 6. 子图内部节点逐个解释

| 节点 | 数量 | 作用 |
|---|---:|---|
| `UNETLoader` | 1 | 加载 `flux-2-klein-4b-fp8` 图像编辑扩散模型 |
| `CLIPLoader` | 1 | 以 `flux2` 类型加载 `qwen_3_4b` 文本/语义编码器 |
| `VAELoader` | 1 | 加载 FLUX.2 VAE，供两张参考图编码和最终解码共用 |
| `CLIPTextEncode` | 1 | 编码商品保真、参考图借鉴和禁止复制竞品元素的规则 |
| `ImageScaleToTotalPixels` | 2 | 分别把商品图和对标图控制到约 `0.6 MP`，降低显存并统一参考信息量 |
| `VAEEncode` | 2 | 分别把两张缩放后的图编码为潜空间 |
| `ReferenceLatent` | 4 | 正/负条件各串入两个参考 latent，让采样器同时知道图 1 和图 2 |
| `ConditioningZeroOut` | 1 | 从正向条件构造零化负向条件；蒸馏 FLUX 工作流不使用传统长负向词 |
| `GetImageSize` | 1 | 从图 1 读取尺寸信息，供输出画布链路参考 |
| `EmptyFlux2LatentImage` | 1 | 建立 `768 × 768`、batch 1 的输出潜空间画布 |
| `RandomNoise` | 1 | 根据 seed 提供初始噪声；默认 `randomize`，调试时可改为固定 seed |
| `KSamplerSelect` | 1 | 选择官方模板使用的 `euler` 采样器 |
| `Flux2Scheduler` | 1 | 生成 FLUX.2 的 4 步噪声计划，并保存目标宽高 |
| `CFGGuider` | 1 | 以 CFG `1` 组合模型和正/负条件；蒸馏模型不需要 SDXL 常见的 6～8 CFG |
| `SamplerCustomAdvanced` | 1 | 汇总 noise、guider、sampler、sigmas 和 latent，完成 4 步采样 |
| `VAEDecode` | 1 | 将采样后的潜空间解码成最终商品主图 |

两个“Reference Conditioning”小子图内部结构相同，分别处理图 1 和图 2：

```text
上一段正向条件 ─┐
                 ├→ ReferenceLatent → 下一段正向条件
图像 → VAEEncode ┤
                 └→ ReferenceLatent → 下一段负向条件
上一段负向条件 ─┘
```

顺序很重要。当前是先图 1 商品，再图 2 对标图；提示词也明确写了 `Image 1` 和 `Image 2` 的职责，不要交换两张输入线。

## 7. 默认提示词怎么读

默认提示词分为六段：

1. 生成新的电商主图，不是简单复制像素。
2. 图 1 是唯一商品身份，要求保留形状、比例、材质、颜色和包装结构。
3. 图 2 只借鉴背景、镜头、比例、视觉层级、色彩和光线。
4. 禁止复制图 2 的商品、品牌、Logo、水印、人物和文字。
5. 要求只有一个商品，并生成合理接触阴影、反射和遮挡。
6. 要求 1:1、干净商业摄影、无额外文字和无贴着商品的几何突起。

替换商品时，在提示词最后补充具体描述，例如：

```text
The product is an unbranded ivory glass skincare cream jar with a champagne gold lid,
smooth cylindrical geometry, opaque ivory cream inside, premium minimal cosmetic packaging.
```

不要写“完全照抄竞品”。我们需要的是视觉规律，不是复制竞品商标、文案或受保护内容。

## 8. 第一次运行步骤

1. 导入本章 JSON。
2. 解决三个缺失模型错误；按 `R` 刷新，必要时重启实例。
3. 图 1 上传[无品牌象牙白面霜罐](assets/test-products/ivory-cream-jar-transparent.png)。
4. 图 2 上传一张单图、1:1、主体清楚、无复杂拼贴的对标商品主图。
5. 在提示词末尾补充面霜罐材质描述。
6. 保持 `768 × 768`、4 步、CFG 1、batch 1。
7. 第一次调试把 `RandomNoise` 的随机化改为固定，便于判断只改提示词后的差异。
8. 运行并记录耗时、显存峰值、输出文件名和 seed。

## 9. 验收标准

第一轮必须同时检查：

- 最终构图明显借鉴图 2，而不是仍然只出现四套固定背景。
- 只有一个面霜罐，没有双商品、假盖子或多余附件。
- 罐体比例、盖子结构、主色和玻璃材质与图 1 基本一致。
- 商品与台面接触自然，两侧没有蓝色三角、翅膀或被遮住一半的道具。
- 背景光线、商品高光和接触阴影大体同向。
- 包装文字和 Logo 若发生漂移，明确标记“不可直接商用”，不能因为整体好看就通过。

本章阶段通过的含义是“双参考编辑链路有效”，不是已经复刻参考站全部产品能力。

## 10. 常见问题

### 10.1 导入后子图显示缺失节点

优先判断 ComfyUI Core 版本。工作流来源是官方最新模板，Desktop 稳定版可能晚于 Nightly。不要安装随机同名节点。

### 10.2 8 GB 显存溢出

按顺序处理：

1. 关闭其他使用 GPU 的程序并重启实例。
2. 确认 batch 仍为 1。
3. 在子图内把两处参考缩放从 `0.6 MP` 降到 `0.4 MP`。
4. 把 `EmptyFlux2LatentImage` 和 `Flux2Scheduler` 的宽高同时从 `768` 改为 `640`。
5. 仍失败时记录完整 OOM 日志、系统内存和启动参数，再决定是否使用云端。

不要只改输出 latent 而忘记 scheduler 中的宽高。

### 10.3 商品包装文字变形

语义编辑模型会重绘像素，这属于已知风险。可选处理：

- 使用更清晰、更大比例的商品输入图。
- 提示词强调 `preserve exact readable label details`。
- 生成后把原商品通过遮罩覆盖回去，但接受环境反射变弱的代价。
- 最终商业图用图像编辑软件恢复真实标签和 Logo。

### 10.4 结果照抄竞品品牌或文案

立即淘汰该图，并加强：

```text
do not copy any brand, logo, watermark, slogan, typography or readable text from Image 2
```

参考图应尽量选没有明显竞品品牌的大构图图，降低误复制风险。

### 10.5 参考图影响太弱

先确认两张图没有接反，再把提示词中的图 2 视觉描述写具体：

```text
use Image 2's warm beige stone tabletop, upper-left softbox lighting,
centered close-up product scale and minimal negative space
```

不要一次上传十张方向不同的参考图。先用一张把最小链路跑通。

## 11. 本章之后

参考图驱动商品主图通过后，再拆成两条独立路线：

1. 普通商品：多参考、批量候选、包装文字恢复与高清放大。
2. 服装商品：模特身份、姿态、服装上身关系和虚拟试穿。

连衣裙案例已经证明服装上身不是普通换背景，不能把两类商品继续塞进同一套工作流。
