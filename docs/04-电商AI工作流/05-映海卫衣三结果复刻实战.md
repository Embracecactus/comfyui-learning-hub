# 05｜映海卫衣公开案例：三结果分支复刻实战

本章复刻映海站“复刻商品主图-卫衣”案例公开可见的输入输出能力。网站没有公开服务端节点图或内部实现，因此这里的“复刻”是：使用相同的公开商品图和对标图，在本地 ComfyUI 中搭建功能方向相似、能够逐节点学习和修改的工作流。

> 定位说明：本章是固定案例的回归测试，因此会固定卫衣文件、网站基线、`1977` 描述和案例版式。它不是任意商品的通用入口。需要替换鞋、瓶、罐或其他商品时，请使用[通用商品自动排版工作流](06-通用商品自动排版工作流.md)。

网站案例公开了三张结果，本章也拆成三条独立工作流：

| 分支 | 网站公开结果方向 | 本地技术 | 配套 JSON |
|---|---|---|---|
| A | 白底平铺商品主图 | BiRefNet 抠图 + 原商品像素合成 | [导入](workflows/ecommerce-yinghai-hoodie-flat-pixel-faithful-birefnet.json) |
| B | 男模全身穿着图 | FLUX.2 Klein：商品 + 米色衬衫男模参考 | [导入](workflows/ecommerce-yinghai-hoodie-model-full-flux2-klein.json) |
| C | 男模近景穿着图 | FLUX.2 Klein：商品 + 蓝色衬衫男模参考 | [导入](workflows/ecommerce-yinghai-hoodie-model-close-flux2-klein.json) |

## 1. 先理解为什么必须拆成三条

RTX 5060 只有约 8 GB 显存。把 BiRefNet、两个 FLUX 采样分支、三张网站基线和所有预览同时塞进一个巨大画布，会带来三个问题：

1. 不知道报错属于抠图、商品合成还是模特生成。
2. 两个 FLUX 分支可能同时进入队列，增加显存和系统内存压力。
3. 修改一个提示词后，无法判断是哪条结果发生了变化。

本章按下面顺序逐条运行：

```text
分支 A：平铺商品原像素合成
        ↓ 验收商品结构和边缘
分支 B：男模全身穿着
        ↓ 验收人物、服装和手部
分支 C：男模近景穿着
        ↓ 验收人物、服装和近景构图
最后：用排版工具添加自有品牌和真实中文卖点
```

网站案例使用 `1` 张商品图、`3` 张对标图，并由未公开的服务端工作流一次返回多张结果。本地第一版按“商品 + 一个最相关参考”分别运行，是适配 8 GB 显存的最小可验证实现，不声称与网站内部算法完全相同。

## 5. 分支 A：白底平铺像素保真

导入：

```text
ecommerce-yinghai-hoodie-flat-pixel-faithful-birefnet.json
```

输出目录：

```text
%LOCALAPPDATA%\Comfy-Desktop\ComfyUI-Shared\output\ecommerce\replica\hoodie-flat-pixel-faithful
```

这条工作流没有扩散模型。BiRefNet 预测商品轮廓后，真正被贴到白底上的仍然是原图 RGB 像素。

### 5.1 16 个节点逐个解释

#### 节点 1｜`MarkdownNote`

只保存模型位置、输出目录和验收说明，不参与执行。将 JSON 发给别人时，工作流自身仍携带必要上下文。

#### 节点 2｜`LoadImage`：商品原图

自动选择 `01-product-1977-hoodie.png`。它有白色旧背景且没有 alpha 通道，因此不能直接当透明商品贴图。

`IMAGE` 分成两路：

- 送入 `RemoveBackground` 预测商品遮罩。
- 送入 `ImageScale`，保留原始商品 RGB 像素。

#### 节点 3｜`LoadBackgroundRemovalModel`

加载 `birefnet.safetensors`。它只提供模型对象，不直接接收图片。

#### 节点 4｜`RemoveBackground`

输入商品图和 BiRefNet 模型，输出 `MASK`：

- 白色代表商品前景。
- 黑色代表背景。
- 灰色代表模型判断的半透明/抗锯齿边缘。

#### 节点 5｜`GrowMask`

默认：

```text
expand  = 0
tapered = true
```

首轮保持 `0`。看到白边时尝试 `-1`；边缘被吃掉时恢复 `0` 或试 `1`。不要一开始就大幅缩小遮罩。

#### 节点 6｜`MaskPreview`

检查商品是否整块为白色、背景是否黑色。帽绳、袖口和衣服外缘若出现断裂，不要继续合成，先处理遮罩。

#### 节点 7｜`ImageScale`：缩放真实商品

参数：

```text
upscale_method = lanczos
width          = 560
height         = 0
crop           = disabled
```

`height = 0` 代表按原图比例自动计算高度，不会把卫衣强行拉伸成 `560 × 固定高度`。

#### 节点 8｜`MaskToImage`

`ImageScale` 只能缩放 `IMAGE`，不能直接接 `MASK`。所以先把黑白遮罩临时转换成三通道图像。

#### 节点 9｜`ImageScale`：同步缩放遮罩

参数：

```text
upscale_method = bilinear
width          = 560
height         = 0
crop           = disabled
```

宽度必须与节点 7 同为 `560`。如果只缩放商品却不缩放遮罩，最终会出现位置错位、商品被切掉或旧背景露出。

#### 节点 10｜`ImageToMask`

选择 `red` 通道，把缩放后的三通道黑白图重新变回 `MASK`。因为三个通道内容相同，选 red/green/blue 结果等价，本章固定 red 方便复现。

#### 节点 11｜`EmptyImage`

创建纯白目标画布：

```text
width      = 576
height     = 1024
batch_size = 1
color      = #FFFFFF / 16777215
```

`576:1024 = 9:16`，是当前 8 GB 机器的练习尺寸，不是网站 `1440 × 2560` 的 2K 输出。

#### 节点 12｜`ImageCompositeMasked`

参数：

```text
x             = 8
y             = 114
resize_source = false
```

目标画布宽 `576`，缩放后的商品源图宽 `560`，水平居中位置：

```text
x = (576 - 560) / 2 = 8
```

`y = 114` 使实际衣服上边缘约落在画布高度的 `15%`，同时保留底部页脚。`resize_source=false` 很重要：商品和遮罩已经同步缩放，合成节点不应再进行第二次缩放。

#### 节点 13｜`PreviewImage`

放大检查帽型、`1977`、袖口、口袋和边缘。这里应当与商品原图完全一致，只发生等比缩放和背景替换。

#### 节点 14｜`SaveImage`

把结果保存到 `ecommerce/replica/hoodie-flat-pixel-faithful` 前缀。

#### 节点 15｜网站对标图 3

断开的 `LoadImage`，只用于观察白底平铺和页脚留白。它不会参与遮罩或合成，也不会把 `CHICERRO` 带进结果。

#### 节点 16｜网站结果 1 基线

同样完全断开，只用于人工比较。网站结果中的竞品文字不是通过标准，禁止复制。

### 5.2 13 条连线

```text
商品图 → RemoveBackground
BiRefNet → RemoveBackground
RemoveBackground → GrowMask → MaskPreview

商品图 → ImageScale（真实 RGB） ──────────────────────┐
GrowMask → MaskToImage → ImageScale → ImageToMask ──┤
EmptyImage（纯白 9:16）───────────────────────────────┤
                                                     └→ ImageCompositeMasked → Preview / Save
```

### 5.3 分支 A 验收

- `1977` 字体、数字和位置没有变化。
- 帽型、口袋、袖口、缝线和面料来自原图。
- 背景纯白，没有旧背景白边。
- 商品居中，顶部和底部留白合理。
- 没有 `CHICERRO` 或其他新增文字。

这五项通过后再进入模特分支。

## 8. FLUX 子图内部为什么有 40 个节点

两个模特 JSON 都派生自 ComfyUI 官方 FLUX.2 Klein 双参考模板。顶层将内部链路折叠成子图，核心节点职责如下：

| 内部节点 | 作用 |
|---|---|
| `UNETLoader` | 加载 4B FP8 图像编辑扩散模型 |
| `CLIPLoader` | 以 `flux2` 类型加载 Qwen 文本/语义编码器 |
| `VAELoader` | 共用 FLUX.2 VAE |
| `CLIPTextEncode` | 理解商品身份、人物参考和替换规则 |
| 两个 `ImageScaleToTotalPixels` | 将商品和人物参考控制在约 `0.6 MP` |
| 两个 `VAEEncode` | 把两张参考图编码为 latent |
| 四个 `ReferenceLatent` | 把两张参考依次加入正/负条件 |
| `ConditioningZeroOut` | 构造蒸馏工作流使用的负向条件 |
| `GetImageSize` | 从图 1 的 9:16 画布读取输出比例 |
| `EmptyFlux2LatentImage` | 创建 batch 1 输出 latent |
| `RandomNoise` | 使用固定 seed 创建初始噪声 |
| `KSamplerSelect` | 使用官方模板的 Euler 采样器 |
| `Flux2Scheduler` | 创建 4 步 FLUX.2 噪声计划 |
| `CFGGuider` | 以 CFG `1` 引导采样 |
| `SamplerCustomAdvanced` | 执行 4 步采样 |
| `VAEDecode` | 把 latent 解码为图片 |

完整内部连线和每个节点的进一步解释见[第 4 阶段文档](04-参考图驱动商品主图工作流.md#6-子图内部节点逐个解释)。不要因为顶层节点显示 UUID 就去 Manager 安装同名插件；它是工作流内嵌子图。

## 9. 为什么本地第一版不直接做网站中文标题

网站结果 2 左上角有：

```text
高克重抗起球面料
宽松插肩 复古百搭
```

本地提示词故意要求 `no typography`，原因是：

1. 扩散模型生成中文可能出现错字、乱码和笔画变形。
2. 网站结果 1 已出现复制参考图 `CHICERRO` 的风险。
3. 电商卖点和品牌属于必须准确的业务数据，应使用真实字体和排版工具。

正确顺序：

```text
先生成无字底图 → 人工验收商品与人物 → 再添加自有品牌和准确中文文案
```

文字排版不属于本章首轮验收。后续可以单独增加 Canvas/SVG/设计软件排版分支，而不是逼扩散模型“画字”。

## 10. 8 GB 显存操作顺序

1. 先运行分支 A。它不加载 FLUX，主要验证 BiRefNet。
2. 分支 A 完成后清空队列。
3. 导入并单独运行分支 B，等待保存结束。
4. 再导入分支 C，不要让 B/C 同时排队。
5. batch 始终保持 `1`。
6. 首轮保持约 `0.6 MP`，不要立即追网站 `2K`。
7. 若 OOM，关闭浏览器硬件加速和其他 GPU 程序，重启实例后一次只跑一个模特分支。

网站 `1440 × 2560` 只是公开结果尺寸，不等于本机第一轮必须直接生成该尺寸。先确保结构正确，再研究放大与精修。

## 11. 常见错误

### 11.1 缺失 `birefnet.safetensors`

只影响分支 A。检查：

```text
ComfyUI-Shared\models\background_removal\birefnet.safetensors
```

不要放在 `checkpoints`、实例目录或 `.download` 文件名下。

### 11.2 `LoadBackgroundRemovalModel` 是红色缺失节点

它是新版 ComfyUI Core 节点，不是 Manager 插件。目标 Core 已具备该源码；若界面仍缺失，先确认导入的是正确 Desktop 实例并重启。

### 11.3 平铺结果商品或遮罩错位

节点 7 和节点 9 的宽度必须相同，当前都是 `560`。两个节点都应使用 `height=0` 和 `crop=disabled`。

### 11.4 模特结果仍穿着衬衫

先确认图 1/图 2 没有接反，再检查提示词是否仍包含“replace only the ... shirt”。不要先用十张参考图增加冲突。

### 11.5 `1977` 或帽型变化

FLUX 模特分支会重新生成穿着像素，不能提供绝对保真。可尝试固定 seed 下加强具体结构描述，但不要无限堆提示词。若连续多次仍漂移，应进入专用虚拟试穿模型路线，而不是声称当前结果可商用。

### 11.6 手指和口袋穿模

这是穿着生成的高风险区域。第一轮要求双手进入袋鼠兜是为了接近网站成片，但如果手部持续失败，可以先改成“双臂自然垂下”验证服装主体，再单独攻克手与口袋交互。

### 11.7 网站基线会不会参与生成

不会。三个 JSON 中的网站结果 `LoadImage` 都没有连线，只是画布上的人工比较尺子。
