# 07｜通用商品 2K 成图与确定性文字排版

上一章已经解决“任意单商品照片如何自动裁边并排到统一白底画布”。本章继续解决两个独立问题：

1. 将 `576×1024` 练习结果提升为与参考站公开结果一致的 `1440×2560` 竖图。
2. 在最终尺寸上添加真实卖点和自有品牌，避免让扩散模型生成乱码或照抄竞品品牌。

工作流：[导入 JSON](workflows/ecommerce-generic-product-layout-2k-branded.json)

```text
任意单商品照片
  → BiRefNet 遮罩
  → ProductLayoutByMask 通用排版（576×1024）
  → RealESRGAN_x4plus（2304×4096）
  → ImageScale 精确收敛（1440×2560）
  ├→ 保存 2K 无字母版
  └→ ProductTextOverlay 卖点
      → ProductTextOverlay 自有品牌
      → 保存 2K 品牌版
```

这里的“2K”沿用电商竖图的常见口语，实际像素必须以 `1440×2560` 为准。

## 1. 为什么先 4×，再缩到精确尺寸

直接把 `576×1024` 用普通插值拉到 `1440×2560`，只能增加像素数量，不能补偿缩小时损失的边缘和材质细节。本工作流先用通用图像模型做 4× 超分辨率，再用 Lanczos 缩到准确交付尺寸：

```text
576 × 1024
  × 4
2304 × 4096
  ↓ Lanczos
1440 × 2560
```

这不是“无损恢复”。超分辨率模型仍会估计高频细节，遇到商品标签、细小文字、二维码、规则纹理时必须和原图比较。品牌文字因此放在最终缩放完成以后，由确定性节点绘制。

ComfyUI 官方的[基础放大教程](https://docs.comfy.org/tutorials/basic/upscale)使用同一条核心链路：`Load Upscale Model → Upscale Image (using Model)`；官方[图像放大指南](https://docs.comfy.org/tutorials/utility/image-upscale)也提醒商品摄影要选择较保守的放大路线。

## 2. 下载并校验放大模型

### 2.1 当前 Desktop 共享模型目录

```text
%LOCALAPPDATA%\Comfy-Desktop\ComfyUI-Shared\models\upscale_models
```

本章使用 `RealESRGAN_x4plus.pth`：通用 RGB 图像 4× 放大模型，约 67 MB。模型不提交到 GitHub，只在本机安装。

在 Windows `cmd.exe` 中执行以下命令。`.download` 后缀会防止未完成文件被 ComfyUI 当成模型：

```bat
set "UPSCALE_DIR=%LOCALAPPDATA%\Comfy-Desktop\ComfyUI-Shared\models\upscale_models"
if not exist "%UPSCALE_DIR%" mkdir "%UPSCALE_DIR%"

curl.exe -L --fail --retry 20 --retry-all-errors --retry-delay 5 -C - ^
  -o "%UPSCALE_DIR%\RealESRGAN_x4plus.pth.download" ^
  "https://hf-mirror.com/amd/realesrgan-x4plus/resolve/main/RealESRGAN_x4plus.pth"

certutil -hashfile "%UPSCALE_DIR%\RealESRGAN_x4plus.pth.download" SHA256
```

正确 SHA-256 必须是：

```text
4fa0d38905f75ac06eb49a7951b426670021be3018265fd191d2125df9d682f1
```

完全一致后再执行：

```bat
move /Y "%UPSCALE_DIR%\RealESRGAN_x4plus.pth.download" "%UPSCALE_DIR%\RealESRGAN_x4plus.pth"
```

如果哈希不同：

- 不要改名，也不要放进工作流运行。
- 不要把一个下载源的残片切换到另一个 URL 续传；不同服务器可能造成错误拼接。
- 删除错误 `.download` 后，从同一个镜像 URL 完整重下。
- 国内镜像不可用时，官方源是 `https://github.com/xinntao/Real-ESRGAN/releases/download/v0.1.0/RealESRGAN_x4plus.pth`。

### 2.2 为什么必须校验

只有文件名正确不代表权重完整。网络中断、服务器不正确响应 Range 请求或不同下载源拼接，都可能得到“大小看似正常、实际不可加载”的文件。哈希验证通过才算安装完成。

## 3. 安装本项目的文字排版节点

本章在上一章节点包中增加：

```text
ProductTextOverlay
显示名：Product Text Overlay
目录：image/ecommerce
```

它使用系统 TrueType/OpenType 字体，在最终画布上按百分比坐标画字。它不调用文生图模型，因此同一参数会得到稳定的位置、字号、颜色和换行。

在 Windows `cmd.exe` 执行：

```bat
set "COMFY_ROOT=%LOCALAPPDATA%\Comfy-Desktop\ComfyUI-Installs\ComfyUI-RTX5060\ComfyUI"
xcopy /E /I /Y "\\wsl.localhost\Ubuntu-22.04\home\lijian\project\work\ComfyUI\custom_nodes\comfyui_product_layout" "%COMFY_ROOT%\custom_nodes\comfyui_product_layout"
```

重启当前实例后，搜索 `Product Text Overlay`。工作流中的节点不应显示红色。

### 3.1 `font_name=auto` 会选什么

节点按以下顺序寻找可用字体：

1. `NotoSansSC-VF.ttf`
2. `NotoSansCJK-Regular.ttc`
3. `msyh.ttc`（微软雅黑）
4. `simhei.ttf`（黑体）
5. `Deng.ttf`（等线）
6. `DejaVuSans.ttf`

当前测试电脑已有 `NotoSansSC-VF.ttf`。换电脑后如果中文显示方框，请安装 Noto Sans SC，或在 `font_name` 下拉框手动选择包含中文字符的字体。

## 4. 17 个节点逐个解释

### 节点 1｜`MarkdownNote`

只记录模型路径、输出尺寸、占位文字和文档位置，不参与运算。以后把 JSON 发给别人时，注意事项不会丢失。

### 节点 2｜`LoadImage`

上传一张只有一个主要商品的照片。横图、竖图、方图和不规则留白都可以；多商品拼图不属于当前模板。

### 节点 3｜`LoadBackgroundRemovalModel`

加载 `birefnet.safetensors`，为背景分割提供模型。

### 节点 4｜`RemoveBackground`

从原图预测前景遮罩。输出的白色部分应完整覆盖商品，黑色部分应是背景。

### 节点 5｜`GrowMask`

遮罩边缘微调，默认 `0`。有白边时先尝试小幅收缩；商品被吃边时小幅扩张，不要一次改很大。

### 节点 6｜`MaskPreview`

检查原始遮罩。主体遗漏、阴影被误识别或背景残留都应在这里解决。

### 节点 7｜`ProductLayoutByMask`

从遮罩自动求商品边界、裁掉原图无关留白、等比缩放，再合成到白色 `576×1024` 画布。默认相对参数沿用上一章已经通过的三形状验收：

```text
最大宽度 88%
最大高度 65%
中心 X 50%
中心 Y 43.5%
裁边安全量 1%
```

此处保留较小工作画布，是为了让 8 GB 显存电脑以可控成本进入 4× 放大链路。

### 节点 8｜`MaskPreview`

检查排版完成后的商品位置与占比。它不参与后面的图像放大。

### 节点 9｜`UpscaleModelLoader`

显示名 `Load Upscale Model`，从 `models/upscale_models` 加载：

```text
RealESRGAN_x4plus.pth
```

它只输出模型描述对象，不会单独生成图片。

### 节点 10｜`ImageUpscaleWithModel`

显示名 `Upscale Image (using Model)`，接收节点 7 的图片和节点 9 的模型，输出 `2304×4096`。

当前 ComfyUI 实现采用分块放大；发生显存不足时会缩小分块重试。因此 8 GB 显存可以尝试，但运行时间和峰值内存仍取决于显卡、驱动和同时加载的其他模型。执行前不要让 FLUX、SDXL 或视频模型同时占满显存。

### 节点 11｜`ImageScale`

使用 `lanczos` 把 4× 结果精确缩到：

```text
width  = 1440
height = 2560
crop   = disabled
```

比例与上游相同，`crop=disabled` 不会切掉商品。

### 节点 12｜`PreviewImage`

预览 2K 无字母版。先放大检查商品标签、logo、边缘、拉链、针脚和规则图案。如果与原图不一致，应优先保留真实商品细节，而不是追求“看起来更锐”。

### 节点 13｜`SaveImage`

保存无字母母版：

```text
ComfyUI-Shared\output\ecommerce\generic\product-layout-2k-clean_*.png
```

这张图最适合继续交给 Photoshop、Figma、Canva 或其他详情页流程。

### 节点 14｜第一个 `ProductTextOverlay`

绘制顶部卖点。导入后的默认值是演示占位符，发布前必须修改：

```text
text                  = 填写真实卖点\n第二行卖点
font_name             = auto
font_size_percent     = 2.4
x_percent             = 7.5
y_percent             = 6.5
anchor                = top_left
align                 = left
color                 = #111111
max_width_percent     = 85
line_spacing_percent  = 25
stroke_width_percent  = 0
keep_inside           = yes
```

参数含义：

| 参数 | 作用 |
|---|---|
| `font_size_percent` | 字号占画布高度的百分比；2.4% 在 2560 高画布上约为 61 px |
| `x/y_percent` | 锚点相对画布左上角的位置，不绑定具体像素 |
| `anchor` | 文本框的哪个角/中心对齐到 x/y |
| `align` | 多行文字内部左对齐、居中或右对齐 |
| `max_width_percent` | 超过该宽度自动换行，中文按字符处理 |
| `line_spacing_percent` | 额外行距相对字号的百分比 |
| `stroke_width_percent` | 描边宽度相对字号的百分比，白底黑字保持 0 即可 |
| `keep_inside` | 文本将越界时自动夹回画布 |

在文本框里直接按 Enter 换行即可；字符串中的 `\n` 也会被转换为换行。

### 节点 15｜第二个 `ProductTextOverlay`

绘制底部自有品牌：

```text
text              = YOUR BRAND
font_size_percent = 3.2
x_percent         = 50
y_percent         = 91
anchor            = bottom_center
align             = center
```

必须替换为自己有权使用的品牌。参考站公开结果中的竞品文字只用于观察版式，本项目不把它复制进模板。

### 节点 16｜`PreviewImage`

预览带字版。检查错别字、卖点真实性、商标授权、文字是否压住商品以及手机缩略图是否可读。

### 节点 17｜`SaveImage`

保存自有品牌版：

```text
ComfyUI-Shared\output\ecommerce\generic\product-layout-2k-branded_*.png
```

## 5. 第一次实践步骤

1. 确认 `RealESRGAN_x4plus.pth` 已下载并通过哈希校验。
2. 复制最新版 `comfyui_product_layout`，完全重启 Desktop 当前实例。
3. 导入 `ecommerce-generic-product-layout-2k-branded.json`。
4. 在节点 2 重新选择商品图片；JSON 不携带你电脑上的媒体内容。
5. 在节点 14 填写两行真实卖点。
6. 在节点 15 把 `YOUR BRAND` 改为自己的品牌；没有品牌时可以填空，空文本会原样透传图片。
7. 点击运行，先看节点 12 的无字母版，再看节点 16 的品牌版。
8. 把两个输出文件都保留，用于判断问题来自放大还是文字排版。

## 6. 不同配置怎么取舍

| 配置或情况 | 建议 |
|---|---|
| NVIDIA 8 GB | 当前默认路线；关闭其他大模型工作流后运行，一次处理 1 张 |
| NVIDIA 12 GB 及以上 | 仍使用当前路线，可更从容地处理连续图片 |
| CPU | 能运行但会很慢；先用普通 `ImageScale` 验证排版 |
| 原图已经非常清晰 | 比较“直接 1440×2560”和 AI 放大版，不要默认 AI 一定更真实 |
| 商品带细小印刷文字/二维码 | 重点逐像素核对；必要时放弃模型锐化，使用原图高分辨率确定性合成 |
| 商品边缘透明/毛发/玻璃 | 先解决 BiRefNet 遮罩，放大模型不能修复错误 alpha |
