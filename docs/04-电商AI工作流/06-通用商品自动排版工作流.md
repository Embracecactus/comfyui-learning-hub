# 06｜通用商品自动裁边与白底排版

固定案例与通用模板必须分开：

| 类型 | 目的 | 可以固定什么 |
|---|---|---|
| 回归测试 | 使用同一输入复现、比较每次修改 | 商品文件、参考图、seed、案例目标 |
| 通用模板 | 替换任意单商品照片后仍能运行 | 只固定业务规则和默认画布比例 |

[映海卫衣三结果分支](05-映海卫衣三结果复刻实战.md)属于回归测试。它出现 `1977`、卫衣专属提示词和网站基线是合理的，但不能当成通用工作流。

本章建立真正的通用白底排版链路：

```text
任意尺寸、任意留白的单商品照片
        ↓
BiRefNet 前景遮罩
        ↓
按遮罩自动求商品边界框
        ↓
删除输入图四周无关区域
        ↓
按目标画布百分比等比缩放并定位
        ↓
纯色背景合成与保存
```

工作流：[导入 JSON](workflows/ecommerce-generic-product-layout-birefnet.json)

## 1. 为什么 Core 节点还差一步

当前 ComfyUI Core 已有 `RemoveBackground`、`GetImageSize`、`ResizeAndPadImage`、`ImageScaleToMaxDimension` 和 `ComfyMathExpression`。这些节点能读取整张输入图尺寸，却没有一个原生节点可以从 `MASK` 自动输出前景边界框。

如果不先按遮罩裁边，一张四周留白很多的商品图仍会被当作整张大图缩放，商品本体可能很小。固定 `width/x/y` 只能修好一张测试图。

因此本项目增加一个小型本地节点：

```text
ProductLayoutByMask
显示名：Product Layout by Mask
目录：custom_nodes/comfyui_product_layout
```

它不使用生成模型，也不改变商品语义；只执行边界框、缩放、位置和 alpha 合成计算。

## 3. 工作流 10 个节点

### 节点 1｜`MarkdownNote`

记录模板范围、节点目录、模型位置和输出目录，不参与执行。

### 节点 2｜`LoadImage`

上传任意一张只含一个主要商品的照片。输入可以：

- 是横图、竖图或方图。
- 四周有不等量留白。
- 有普通摄影背景。
- 分辨率与目标画布不同。

不要首轮上传多商品拼图或多角度九宫格。

### 节点 3｜`LoadBackgroundRemovalModel`

加载 `birefnet.safetensors`，只提供背景分割模型。

### 节点 4｜`RemoveBackground`

根据商品照片生成白色前景、黑色背景的 `MASK`。

### 节点 5｜`GrowMask`

默认 `0`。只有出现白边或商品边缘被吃时才进行 `-1/0/1` 小范围调整。

### 节点 6｜`MaskPreview`

检查原始遮罩。遮罩错误会直接导致后面的自动边界框错误。

### 节点 7｜`ProductLayoutByMask`

通用排版核心。输入原始 RGB 和前景遮罩，输出白底结果与已经定位到画布上的遮罩。

默认参数：

```text
canvas_width        = 576
canvas_height       = 1024
max_width_percent   = 88.0
max_height_percent  = 65.0
center_x_percent    = 50.0
center_y_percent    = 43.5
mask_threshold      = 0.1
crop_padding_percent = 1.0
background_color    = #FFFFFF
interpolation       = lanczos
allow_upscale       = yes
```

这些是相对画布的业务参数：

- `max_width_percent=88`：商品最大宽度为画布宽度的 88%。
- `max_height_percent=65`：商品最大高度为画布高度的 65%。
- 两项同时生效，先触及哪一项就由哪一项限制缩放。
- `center_x_percent=50`：水平中心在画布正中。
- `center_y_percent=43.5`：商品中心略高于画布正中，为底部卖点区留空间。
- `crop_padding_percent=1`：在遮罩边界外保留很小安全边，避免裁掉抗锯齿边缘。

处理公式：

```text
最大商品宽 = canvas_width  × max_width_percent  / 100
最大商品高 = canvas_height × max_height_percent / 100

scale = min(最大商品宽 / 裁边后宽度,
            最大商品高 / 裁边后高度)

x = canvas_width  × center_x_percent / 100 - 缩放后宽度 / 2
y = canvas_height × center_y_percent / 100 - 缩放后高度 / 2
```

换成鞋子、瓶子或服装时，公式会根据遮罩边界重新计算，不需要手填某张图专属的 `560/x=8/y=114`。

### 节点 8｜`MaskPreview`

查看经过自动裁边、等比缩放和定位后的画布遮罩。它用于判断商品占比，不是再次抠图。

### 节点 9｜`PreviewImage`

检查最终背景、商品边缘、比例和位置。

### 节点 10｜`SaveImage`

输出到：

```text
%LOCALAPPDATA%\Comfy-Desktop\ComfyUI-Shared\output\ecommerce\generic
```

## 4. 哪些参数是通用规则，哪些仍是预设

通用不代表“没有参数”。目标平台比例和业务安全区本来就需要配置：

| 参数 | 是否商品专属 | 说明 |
|---|---|---|
| 输入图片 | 否 | 每次替换 |
| 前景边界 | 否 | 运行时从遮罩计算 |
| 缩放宽高 | 否 | 运行时按百分比计算 |
| x/y | 否 | 运行时按中心百分比计算 |
| 画布 576×1024 | 是版式预设 | 代表 9:16，可改成其他平台尺寸 |
| 最大宽 88%、最大高 65% | 是业务预设 | 对所有商品使用同一安全框，可整体调整 |
| 中心 50%、43.5% | 是业务预设 | 控制主视觉区，不绑定某个商品像素 |

例如切换为 1:1 主图，只改：

```text
canvas_width  = 1024
canvas_height = 1024
```

商品边界框、缩放尺寸和居中位置会重新计算。

## 5. 通用性的边界

本模板适用于“一个主要商品 + 确定性白底排版”，不是所有电商任务的万能模型：

- 多商品组合需要分别抠图和布局，不能把整组当一个前景框。
- 透明玻璃、网纱、毛发等边缘先受 BiRefNet 遮罩质量限制。
- 模特换装不是平铺排版，应进入独立虚拟试穿/多参考生成路线。
- 参考图风格迁移使用[通用 FLUX.2 Klein 双参考工作流](workflows/ecommerce-reference-main-image-flux2-klein.json)，不应把卫衣专属提示词复制过去。
- 精确中文、价格和品牌仍应在结果通过后用确定性排版工具添加。

## 6. 最小通用验收矩阵

至少使用三种形状验证，不能只测卫衣：

| 商品 | 主要限制应来自 | 验收重点 |
|---|---|---|
| 横向鞋/包 | 最大宽度 | 左右安全边一致、商品不变形 |
| 竖向瓶/精华 | 最大高度 | 顶底不被裁掉、瓶身垂直 |
| 方形罐/服装 | 宽或高自动选择 | 大小稳定、四周留白合理 |

每次记录输入尺寸、遮罩、输出尺寸、主体占比和失败原因。只有三类都通过，才把这条白底链路标记为通用模板通过。

用户在 Desktop 实际导入通用 JSON，选择 `01-product-1977-hoodie.png`，不修改排版参数直接运行。


使用白色容差 `1%` 计算前景边界：

| 项目 | 前景边界 | 宽度占比 | 高度占比 | 左边距 | 顶边距 |
|---|---|---:|---:|---:|---:|
| 通用本地输出 | `495×566 +41+163` | `85.94%` | `55.27%` | `7.12%` | `15.92%` |
| 网站白底结果的商品区 | `1253×1447 +110+389` | `87.01%` | `56.52%` | `7.64%` | `15.20%` |
| 绝对百分点差 | — | `1.07` | `1.25` | `0.52` | `0.72` |

结论：

- 主体大小、水平安全边和顶部位置均已进入网站结果的同一版式区间，无需卫衣专属像素坐标。
- `1977`、帽型、插肩线、口袋、袖口和面料保持原商品图，未被扩散模型重画。
- 未见明显白边或遮罩侵蚀，`GrowMask=0` 通过。
- 网站结果是 `1440×2560`，并带竞品 `CHICERRO` 页脚；本地结果是练习分辨率且故意不复制竞品文字。
- 精华瓶、面霜罐和卫衣三种前景形状已经共用同一套相对参数通过，因此这条确定性单商品白底排版链路标记为通过。

这个“通过”仅针对单商品自动裁边和排版，不扩大为模特换装、多商品组合或网站全部生成能力。
