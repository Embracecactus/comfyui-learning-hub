## 3. 为什么另外准备 9:16 商品输入

官方 FLUX.2 工作流会从图 1 读取宽高，并把它用于输出 latent 和 scheduler。若直接使用 `534 × 642` 商品原图，本地结果不会与网站 `9:16` 画幅一致。

`01b` 文件没有用 AI 重绘商品，只把原图等比缩放后放到白色 `576 × 1024` 画布上：

```bash
convert -size 576x1024 canvas:white \
  \( 01-product-1977-hoodie.png -resize 480x576 \) \
  -gravity north -geometry +0+90 -composite \
  01b-product-1977-hoodie-9x16-canvas.png
```

这样本地首轮输出约为 `576 × 1024`，比例与网站基线一致，同时保留原商品像素作为身份参考。

## 5. 第一次运行

1. 将图片复制到上面的 `ComfyUI-Shared\input\yinghai-hoodie-comparison`，不要放到实例源码目录。
2. 重启 `ComfyUI-RTX5060` 实例，或进入画布后按 `R` 刷新模型和输入文件列表。
3. 重新将 `ecommerce-yinghai-hoodie-comparison-flux2-klein.json` 拖入 ComfyUI。若第一次导入时文件不存在，节点选择可能已经被界面清空，仅刷新不一定恢复，必须重新导入或手动重选。
4. 确认两个生成输入和右侧网站基线都出现预览，不再显示“所需的媒体输入未选择文件”。
5. 确认三个模型下拉框命中 `flux-2-klein-4b-fp8.safetensors`、`qwen_3_4b.safetensors`、`flux2-vae.safetensors`。
6. 保持 4 步、CFG `1`、batch `1` 和固定 seed，不要先改提示词。
7. 点击“运行”，等待本地结果保存。
8. 将本地结果与右侧 `网站公开结果基线` 节点逐项比较，并保存运行耗时、显存峰值和输出文件名。

右侧基线节点没有连接到采样器。它只是一把视觉尺子，不会泄漏到本地生成链路。

### 三个节点同时提示“缺少输入”

这通常不是 JSON 或模型损坏，而是图片放错输入根目录。ComfyUI Desktop 会通过启动参数把输入、输出改到 `ComfyUI-Shared`；实例源码里的 `ComfyUI\input` 不再是运行时目录。

修复顺序：

1. 检查 `ComfyUI-Shared\input\yinghai-hoodie-comparison` 中是否存在 `01b`、`02`、`03` 三个文件。
2. 重启实例或按 `R`。
3. 重新导入专用 JSON。
4. 仍为空时，在三个 `LoadImage` 节点中分别手动选择对应文件。

## 6. 验收表

| 检查项 | 通过标准 | 常见失败 |
|---|---|---|
| 商品身份 | 单件黑色连帽卫衣，整体轮廓接近商品图 | 变成衬衫、外套或出现第二件衣服 |
| 胸前数字 | 清楚且仍为 `1977` | 数字缺失、变形或改成其他数字 |
| 结构 | 帽子、插肩袖、袋鼠兜、袖口和下摆保留 | 口袋消失、袖型改变、结构粘连 |
| 材质与颜色 | 黑色颗粒/杂色面料基本保留 | 变成纯色、浅色或光滑皮革 |
| 版式借鉴 | 暖白背景、居中、留白充分、9:16 商业目录感 | 仍像原始上传图，或背景过于复杂 |
| 品牌安全 | 没有 `CHICERRO` 或其他竞品文字/Logo | 复制参考图品牌或生成乱码文字 |
| 画面完整性 | 只有一件商品，接触阴影自然 | 多商品、人物、配件、悬浮或畸形阴影 |

首轮通过的含义是：本地双参考链路确实同时利用了商品身份与参考版式。它不代表 `1977` 已达到印刷级文字保真，也不代表本地模型整体追平网站服务。

第三轮说明提示词继续变长也无法让语义编辑模型稳定复制服装几何。模型理解了“张开帽子”，却仍然用重新设计帽型的方式执行，而不是保留商品原像素。继续做第四轮同类提示词实验的收益已经很低。

### 10.2 停止升分辨率

当前不进入 `0.8 MP`。提高分辨率只会更清楚地放大错误帽型和虚构标签，不会自动恢复商品身份。必须先改变工作流结构，再讨论高清输出。

### 10.3 下一条采用混合像素保真工作流

对这类“白底单件服装 + 页脚品牌版式”，更可靠的路线是：

```text
原商品照片
  └→ BiRefNet 抠图 → 原商品像素 + 前景遮罩 ───────────┐
                                                        ├→ 精确缩放和定位 → 遮罩合成 → 成片
FLUX / 纯色节点只生成背景、留白和无品牌版式 ──────────┘
                                                        └→ 后期添加自有品牌文字
```

这条路线把职责分开：

- FLUX 负责可变化的背景、色调和版式，不再重绘真实商品。
- BiRefNet 提取商品轮廓，`ImageCompositeMasked` 使用原始商品像素完成合成。
- 商品的 `1977`、帽型、口袋、缝线和面料不会被生成模型改写。
- 品牌文字由排版节点或外部设计工具添加，不让扩散模型生成文字。

本案例的目标背景本来就是纯白，所以甚至可以跳过 FLUX，直接使用 `EmptyImage` 创建 9:16 白色画布。这会更快、更稳定，也更符合电商 SKU 保真要求。需要复杂场景时，再让 FLUX 只生成无商品背景。

对应基础链路见[自动抠图与白底主图](../02-自动抠图与白底主图工作流.md)。截至第三轮检查，目标 Desktop 的共享目录中尚未发现：

```text
%LOCALAPPDATA%\Comfy-Desktop\ComfyUI-Shared\models\background_removal\birefnet.safetensors
```

因此下一步应先按第二章下载并校验 BiRefNet，再派生“9:16 服装页脚版式 + 原像素商品合成”专用工作流。
