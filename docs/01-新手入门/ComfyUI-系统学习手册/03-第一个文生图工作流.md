# 03｜第一个文生图工作流

本章从空白画布搭建一条最经典的 Stable Diffusion 文生图链。不同模型可能需要专用文本编码、潜空间或采样设置；第一次练习应使用官方基础模板对应的模型。

## 1. 最终结构

需要 7 个节点，其中 `CLIP Text Encode` 使用两次：

```text
Load Checkpoint ── MODEL ───────────────────────────────┐
      │                                                 │
      ├─ CLIP ─→ CLIP Text Encode（正向）─ positive ───┤
      │                                                 ├→ KSampler ─ LATENT ─→ VAE Decode ─ IMAGE ─→ Save Image
      ├─ CLIP ─→ CLIP Text Encode（负向）─ negative ───┤                              ↑
      │                                                 │                               │
      └─ VAE ───────────────────────────────────────────┴───────────────────────────────┘

Empty Latent Image ───────────────────── latent_image ──┘
```

数据先在潜空间中生成，最后才解码成肉眼可见的图片。

## 2. 添加 Load Checkpoint

双击画布，搜索 `Load Checkpoint`，选择内部类型为 `CheckpointLoaderSimple` 的节点。

- `ckpt_name`：选择 `models/checkpoints/` 下的一体式模型。
- `MODEL`：给 KSampler 去噪。
- `CLIP`：给两个文本编码节点理解提示词。
- `VAE`：给 VAE Decode 解码。

如果下拉框为空或显示 `null`，说明没有检测到 checkpoint。检查目录、扩展名和启动日志，然后按 `r` 刷新或重启。

## 3. 添加两个 CLIP Text Encode

添加两个 `CLIP Text Encode (Prompt)`：

- 第一个重命名为“正向提示词”，写想出现的内容。
- 第二个重命名为“负向提示词”，写希望避免的内容。
- 将 Load Checkpoint 的同一个 `CLIP` 输出分别接到两个节点的 `clip`。

练习提示词：

```text
正向：a cozy wooden cabin beside a lake, sunrise, soft mist, cinematic light, detailed
负向：blurry, low quality, distorted, watermark, text
```

提示词是否适合英文、自然语言还是标签式写法，取决于模型的文本编码器和训练方式。先照模型官方示例写。

## 4. 添加 Empty Latent Image

添加 `Empty Latent Image`：

- `width`：512
- `height`：512
- `batch_size`：1

它不是一张黑图，而是为采样器创建指定尺寸的空潜空间。SD1.5 常从 512 附近练习；SDXL 常从 1024 附近练习。不要把这一经验套到所有新模型上。

## 5. 添加 KSampler

添加 `KSampler`，先使用保守的练习参数：

| 参数 | 建议起点 | 含义 |
|---|---:|---|
| `seed` | 任意整数 | 决定初始噪声；固定后便于对比 |
| `steps` | 20 | 去噪迭代次数 |
| `cfg` | 7.0 | 提示词引导强度 |
| `sampler_name` | `euler` 或模型示例值 | 去噪算法 |
| `scheduler` | `normal` 或模型示例值 | 每一步如何分配噪声水平 |
| `denoise` | 1.0 | 文生图从完整噪声开始 |

连接四个必需输入：

- `model` ← Load Checkpoint 的 `MODEL`
- `positive` ← 正向 CLIP Text Encode 的 `CONDITIONING`
- `negative` ← 负向 CLIP Text Encode 的 `CONDITIONING`
- `latent_image` ← Empty Latent Image 的 `LATENT`

参数不是越高越好。步数超过模型收益区间只会更慢，CFG 太高可能导致颜色过饱和、边缘发硬或画面崩坏。

## 6. 添加 VAE Decode

添加 `VAE Decode`：

- `samples` ← KSampler 的 `LATENT`
- `vae` ← Load Checkpoint 的 `VAE`
- 输出 `IMAGE` 是可以预览和保存的像素图片。

若出现纯黑图、颜色异常或尺寸错误，可能是 VAE 与模型不匹配，也可能是精度或显存问题。

## 7. 添加 Save Image

添加 `Save Image`：

- `images` ← VAE Decode 的 `IMAGE`
- `filename_prefix`：例如 `learning/text-to-image`

斜杠通常会在输出目录下形成子目录。最终图片默认写到 ComfyUI 的 `output/`。保存图像通常还会写入工作流元数据，便于把 PNG 拖回 ComfyUI 恢复工作流；若图片被平台压缩或清洗元数据，这个能力会丢失。

## 8. 第一次运行

运行前逐项检查：

- Checkpoint 已选择，不是 `null`。
- KSampler 四个输入都有线。
- VAE Decode 的 `samples` 和 `vae` 都已连接。
- Save Image 已接到 `IMAGE`。
- 分辨率没有误填成 5120 × 5120。
- 队列里没有大量重复任务。

点击 `Run`。第一次运行会加载模型，通常比第二次慢。终端中看到进度条走完、Save Image 显示结果，即成功。

## 9. 用控制变量做四次实验

固定提示词和其他参数，每次只改一项：

1. 固定 seed 连续运行两次，观察能否基本复现。
2. 只改变 seed，观察构图如何变化。
3. 固定 seed，把 steps 从 20 改成 8，再改成 30。
4. 固定 seed，把 cfg 从 7 改成 3，再改成 12。

这比一次改五个参数更容易形成可靠直觉。

## 10. 常见失败

| 现象 | 最可能原因 | 处理 |
|---|---|---|
| `ckpt_name: null` / 下拉为空 | 模型缺失或目录错误 | 放入 `models/checkpoints/` 后刷新 |
| `Required input is missing` | 必需端口没接 | 根据报错节点和输入名补线 |
| 类型不匹配、线接不上 | 接错数据类型 | 重新核对 `MODEL/CLIP/VAE/LATENT/IMAGE` |
| CUDA out of memory | 分辨率、批量或模型过大 | 先降分辨率和 batch，再看第 8 章 |
| 出图全黑 | VAE/精度/模型不匹配 | 换模型配套 VAE，查看终端完整错误 |
| 图片没变化 | seed 固定且输入未变，缓存正常 | 修改提示词或 seed；确认 seed 生成后行为 |
| 一直生成 | 队列里提交了多次 | 打开 Queue 取消多余任务 |

## 11. 保存学习版本

把工作流保存为 `01-basic-text-to-image.json`。建议在画布上添加三个 Note：

- 使用的模型及来源。
- 当前分辨率与采样器建议。
- 这次实验得到的结论。

仓库里已有一个基础示例工作流，可从 [文生图示例](../examples/文生图.json) 加载；其中的模型名需要按本机模型修改。
