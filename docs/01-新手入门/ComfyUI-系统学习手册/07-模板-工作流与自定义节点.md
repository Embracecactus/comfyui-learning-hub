# 07｜模板、工作流与自定义节点

## 1. 官方模板是新模型的首选入口

打开左侧 `Templates`，或从 `Workflow → Browse Workflow Templates` 进入。模板的价值不仅是“省得连线”，更重要的是它明确了：

- 模型组件和目录。
- 专用文本编码节点。
- 潜空间尺寸和帧数约束。
- 推荐 sampler、scheduler、steps 和 guidance。
- 模型是否需要额外参考图、音频或控制条件。

加载模板时 ComfyUI 会检查缺失模型。Desktop 通常可直接下载；其他安装方式可能打开浏览器并提示保存目录。

## 2. 保存工作流的三种方式

### 工作流 JSON

最适合版本管理和分享。命名建议包含任务与版本：

```text
portrait-sdxl-v01.json
portrait-sdxl-v02-controlnet.json
```

### 带元数据的 PNG/WebP

ComfyUI 保存的图片通常可嵌入工作流，拖回画布即可恢复。社交平台、截图和图片压缩工具可能删除元数据，所以不能把图片当作唯一备份。

### 本地工作流库

新版界面可以把工作流保存在用户目录并从左侧 Workflows 管理。重要工作流仍建议导出 JSON 并纳入备份。

## 3. 拿到社区工作流后的正确检查顺序

1. 先另存副本，不覆盖自己的稳定工作流。
2. 查看缺失节点列表，记录每个节点包的准确仓库。
3. 查看缺失模型名，不要仅按同名文件盲目下载。
4. 确认工作流面向的 ComfyUI 版本、模型架构和显存。
5. 检查输出路径、网络/API 节点和可能上传数据的节点。
6. 阅读自定义节点仓库 README、依赖和许可。
7. 安装后重启，检查控制台是否有 `IMPORT FAILED`。
8. 先以低分辨率、batch 1 运行。

工作流 JSON 本身通常是配置，但它引用的第三方节点是可执行 Python/JavaScript 代码，应像安装普通软件一样审查来源。

## 4. 安装自定义节点

官方当前推荐优先使用 ComfyUI Manager。具体步骤会随版本变化，请参照 [官方自定义节点安装指南](https://docs.comfy.org/zh/installation/install_custom_node)。

Manager 的典型流程：

1. 打开 Manager/节点管理。
2. 按缺失节点或仓库名称搜索。
3. 核对作者、仓库地址、最近维护和说明。
4. 安装并重启 ComfyUI。
5. 查看启动日志，不要忽略依赖冲突。

手动安装的一般思路：把仓库放到 `ComfyUI/custom_nodes/`，再用 **ComfyUI 自己的 Python 环境** 安装该节点依赖。Desktop、Portable、源码版的 Python 路径不同，不能混用。

## 5. 为什么不要一次装“整合包大全”

- 不知道哪个包提供哪个节点。
- Python 依赖容易互相覆盖。
- 更新后难以定位兼容性问题。
- 重名节点和前端扩展可能互相影响。
- 启动更慢，安全审查范围更大。

按工作流实际需要逐个安装，并记录版本，是最省排错时间的做法。

## 6. 更新策略

更新前：

- 导出重要工作流。
- 记录能运行的 ComfyUI、前端、节点包和模型版本。
- 查看自定义节点是否声明兼容。
- 不在交付前临时全量更新。

更新后：

- 先启动空工作流，查看 `IMPORT FAILED`。
- 运行最基础文生图。
- 再运行含 LoRA、ControlNet 和自定义节点的工作流。
- 失败时用“移除一半插件/分支”的方法缩小范围。

## 7. 整理大型工作流

推荐从左到右分成：

```text
[输入与模型] → [提示与条件] → [潜空间与采样] → [解码] → [后处理] → [保存]
```

每个区域：

- 用 Group 分组并设不同颜色。
- 用 Note 写模型路径、下载地址和关键参数。
- 用 Reroute 整理长线。
- 给重复节点改清晰标题，例如“正向-主体”“正向-背景”。
- 稳定主链与实验分支分开保存。

## 8. 分享工作流时应附带什么

- 工作流 JSON。
- ComfyUI 版本或日期。
- 所有模型的准确名称、来源和目录；有条件时附哈希。
- 自定义节点仓库与版本/commit。
- 推荐显存、分辨率、batch 和实测耗时。
- 输入素材要求。
- 生成步骤和已知限制。
- 不可重新分发的模型只给官方下载页，不要把权重打包进去。
