# 04｜模型、提示词与采样参数

## 1. 一体式模型和分体式模型

### 一体式 Checkpoint

`Load Checkpoint` 一次输出 `MODEL`、`CLIP` 和 `VAE`。传统 SD1.5、SD2、SDXL 工作流常见这种形式，最适合用来理解基础链。

### 分体式模型

新模型常把不同组件分别发布：

```text
Load Diffusion Model ─→ MODEL
Load CLIP / DualCLIP ─→ CLIP
Load VAE ─────────────→ VAE
```

分体式不是“少了东西”，而是把组件拆开，便于替换、量化和复用。必须使用模型说明指定的文本编码器、VAE、精度和专用条件节点；不能只看文件扩展名随意混搭。

## 2. 模型系列决定工作流

| 模型系列 | 常见原生尺寸 | 文本/条件特点 | 新手注意 |
|---|---:|---|---|
| SD1.5 | 512 附近 | 常见 CLIP 标签式提示 | 资源少、生态成熟，适合练基础 |
| SDXL | 1024 附近 | 双文本编码信息，基础节点可封装处理 | 显存和计算量高于 SD1.5 |
| SD3 / FLUX 等 | 依具体模型 | 常使用分体加载、专用 guidance/conditioning | 直接加载官方模板，不照搬 SD1.5 参数 |
| 视频/音频/3D 模型 | 依模型 | 有帧数、时长、音频或几何条件 | 节点链高度专用，先读模型教程 |

“原生尺寸”是常见训练分辨率范围，不等于只能生成这一个尺寸。宽高通常应满足节点步长要求，且像素越多越占显存。

## 3. 模型文件名看不出的东西

使用模型前至少确认：

- 基础架构：SD1.5、SDXL、Flux、Wan 等。
- 这是完整 checkpoint、扩散模型、LoRA、VAE 还是 ControlNet。
- 推荐分辨率、采样器、scheduler、steps 和 guidance/CFG。
- 是否需要触发词、专用文本编码器或专用 VAE。
- 权重精度与量化方式，例如 fp16、bf16、fp8；硬件是否支持。
- 许可是否允许你的用途。

工作流报错不一定是线接错，也可能是组件架构不兼容。

## 4. 提示词的正确思路

提示词不是统一语言。先看模型卡和官方模板，再选择写法。

可以按下面的层次组织：

```text
主体 + 动作/状态 + 场景 + 构图/镜头 + 光线 + 材质/风格 + 质量要求
```

示例：

```text
a red fox sitting beside a quiet forest stream,
full body, eye-level shot, centered composition,
soft morning fog, rim light, natural fur detail,
cinematic photography
```

中文含义清楚比盲目堆词重要。支持自然语言的模型可以直接写完整句子；老式标签模型更常见逗号分隔的短语。

## 5. 正向和负向提示词

- 正向：告诉模型希望出现什么。
- 负向：提供“不希望出现”的条件，不是后期删除命令。
- 某些新模型弱化、忽略或不使用传统负向提示；以模板为准。
- 大量互相矛盾的负向词会限制生成空间，未必提升质量。

排查提示词时先缩短：只保留主体、场景和一个风格。基础构图正确后再加细节。

## 6. 权重语法

部分 CLIP 提示词支持类似：

```text
(red dress:1.2)
(background:0.8)
```

它表示调整对应片段的权重，不保证每个模型都以同样方式响应。权重过高容易产生重复、锐化、颜色溢出或结构变形。建议从 `1.05～1.2` 小幅调整，而不是直接堆到很高。

## 7. Seed：复现的起点，不是作品编号

`seed` 决定随机噪声。固定以下条件时，相同 seed 通常可得到相同或非常接近的结果：

- 模型及其哈希相同。
- 工作流和所有参数相同。
- ComfyUI、PyTorch、设备后端和算法实现相容。

升级软件、换显卡后端、启用非确定性优化或更换模型文件，都可能造成差异。因此“同 seed 必然逐像素一致”不是跨环境保证。

seed 控件常有生成后行为：

- `fixed`：下次仍用同一 seed。
- `increment` / `decrement`：每次递增/递减。
- `randomize`：每次随机。

做参数对比时用 `fixed`。

## 8. Steps：够用即可

steps 是去噪步数。更多步数通常更慢，但不会无限提高质量。

- 普通模型可从 20 步附近开始。
- 蒸馏、Turbo、Lightning、LCM 类模型可能只需很少步数。
- 某些高质量或视频模型需要自己的推荐区间。

最有效的办法：固定 seed，测试 8、16、24、32 步，找到肉眼收益开始变小的位置。

## 9. CFG / Guidance：服从与自然度的平衡

传统 CFG 越高，模型越用力贴近提示词；过高可能导致发硬、过饱和、噪点和细节破坏。常规 SD 可从 `5～8` 试起。

注意：Flux 等模型可能使用专用 `FluxGuidance`，某些蒸馏模型推荐非常低甚至特殊的 guidance。节点里出现 `cfg` 不代表所有模型都应填 7。

## 10. Sampler 和 Scheduler

### Sampler

采样器决定根据模型预测值如何从当前噪声走向下一步。常见选择：

- `euler`：简单、快，适合建立基准。
- `euler_ancestral`：加入随机性，结果风格可能更活跃。
- `dpmpp_2m` / `dpmpp_2m_sde`：常见高质量选择。
- `lcm`：通常配合 LCM/蒸馏模型与少步数，不是通用加速开关。

### Scheduler

scheduler 决定各步采用哪些噪声水平。常见 `normal`、`simple`、`karras` 等。采样器和 scheduler 是组合，不应孤立比较。

模型作者给了组合时先照抄。没有建议时，选一个基准组合，固定 seed 后再比较。

## 11. Denoise：重绘强度

- `1.0`：几乎从完整噪声开始；文生图通常用它。
- 接近 `0`：大部分保留输入潜空间，改动很小。
- 中间值：保留原图结构和重新生成之间折中。

denoise 与 steps 共同决定实际采样区间。图生图中最值得做的是固定 seed，比较 `0.25 / 0.5 / 0.75 / 1.0`。

## 12. 分辨率与 Batch

像素数量约等于 `width × height × batch_size`。宽高各翻倍，像素变成 4 倍，显存和耗时通常显著增加。

- `batch_size` 是一次处理的图片数量。
- 一次队列多次运行与大 batch 的显存行为不同。
- 新手先 `batch_size = 1`。
- 先用原生尺寸附近生成，再放大，比直接生成超大图更稳。

## 13. 一套可靠的调参顺序

1. 使用官方模板的模型和默认参数，确认能跑。
2. 固定 seed，先调提示词和构图。
3. 固定其他项，选择 steps。
4. 再测试 CFG/guidance。
5. 最后比较 sampler/scheduler。
6. 构图满意后再放大、修脸或后处理。
