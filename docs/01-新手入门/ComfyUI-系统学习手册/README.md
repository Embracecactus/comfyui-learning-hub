## 30 秒理解 ComfyUI

ComfyUI 是一张“数据加工流水线”。每个方框是一个节点，连线传递数据：

```text
模型文件 ─→ 加载模型 ─┬→ 文本编码 ─────────────┐
                     ├→ 扩散模型 ─┐           │
                     └→ VAE ──────┼──────┐    │
空潜空间 ─────────────────────────→ 采样器 ─→ VAE 解码 ─→ 保存图片
                                   ↑
                            正向/负向条件
```

只要记住下面 6 种数据，已经能看懂大多数基础工作流：

| 端口类型 | 白话解释 | 常见来源 | 常见去向 |
|---|---|---|---|
| `MODEL` | 负责把噪声逐步变成内容的扩散模型 | Load Checkpoint | KSampler |
| `CLIP` | 负责理解提示词的文本编码器 | Load Checkpoint / Load CLIP | CLIP Text Encode |
| `CONDITIONING` | 文本、图像或控制信息编码后的“要求” | CLIP Text Encode | KSampler 的 positive/negative |
| `LATENT` | 模型内部处理的压缩图像数据 | Empty Latent / VAE Encode | KSampler / VAE Decode |
| `VAE` | 在真实图片与潜空间之间转换 | Load Checkpoint / Load VAE | VAE Encode / Decode |
| `IMAGE` | 人能看到的像素图片 | Load Image / VAE Decode | Save Image / 图像处理节点 |

## 本手册的节点覆盖范围

“每个节点”需要先划清范围，否则第三方节点没有上限：安装一个节点包就可能多出几十到几百个节点。

本手册按以下范围处理：

- 详细讲解日常最常用的 Comfy Core 节点，包含用途、输入、输出、参数、接法和常见错误。
- 完整索引当前仓库 `ComfyUI 0.33.0` 可载入的 **639 个非 API 内置节点**，记录显示名、内部类名、类别、输入和输出。
- 单独解释前端节点，例如 Reroute、Note、Primitive 和 Group；它们不一定出现在 Python 节点注册表中。
- 不把 `custom_nodes/` 第三方节点和需要账号/额度的云端 API 节点混入核心索引。第三方节点应以作者 README、节点内帮助和配套示例为准。
- 节点随 ComfyUI 更新很快；本手册的源码快照日期为 **2026-08-26**。节点不存在时，先核对版本、依赖和工作流来源。

## 推荐的学习方法

1. 先加载官方模板并成功运行，不要一开始就装大量插件。
2. 手动搭一次基础文生图，理解每条线传的是什么。
3. 每次只改一个变量，例如只改 `seed` 或只改 `denoise`，对比结果。
4. 保存能运行的版本，再复制工作流做实验。
5. 看见陌生节点先看类别、输入和输出，再看参数；不要仅凭节点中文译名猜。
6. 遇到错误先记录红色节点、完整报错、模型名、显卡和操作步骤。

## 文档约定

- 节点名优先写官方英文显示名，并在首次出现时补充中文解释。不同中文语言包的翻译可能不同，英文名更适合搜索。
- `输入 → 节点 → 输出` 表示数据流向。
- “接到”指从上游输出端口拖线到下游同类型输入端口。
- 参数建议是起点，不是所有模型的固定答案。模型官方示例优先级高于通用经验值。
- 文档中的路径都以 ComfyUI 数据目录为起点；Desktop、便携版和源码版的实际根目录可能不同。
