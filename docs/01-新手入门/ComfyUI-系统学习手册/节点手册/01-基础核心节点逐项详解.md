# 基础核心节点逐项详解

本章详细解释通用图像工作流中最高频的 Comfy Core 节点。显示名以英文为准，括号内是常见内部类名；中文界面的翻译可能略有不同。

## 一、模型加载节点

### 1. Load Checkpoint（`CheckpointLoaderSimple`）

- **作用**：加载一体式 checkpoint，一次得到扩散模型、文本编码器和 VAE。
- **输入/参数**：`ckpt_name`，从 `models/checkpoints/` 选择文件。
- **输出**：`MODEL` → 采样器；`CLIP` → 文本编码；`VAE` → 编码/解码。
- **典型接法**：基础 SD1.5/SDXL 文生图的起点。
- **常见坑**：下拉为空通常是目录或数据根目录错误；文件能选中不代表架构一定与工作流兼容。

### 2. Load Checkpoint With Config（`CheckpointLoader`，已弃用）

- **作用**：使用外部配置文件加载旧式 checkpoint。
- **输入**：checkpoint 名和 config 名。
- **输出**：`MODEL`、`CLIP`、`VAE`。
- **适用**：只有旧工作流明确依赖单独 YAML 配置时才保留。
- **常见坑**：新工作流不要主动使用；优先迁移到 Load Checkpoint 或分体加载器。

### 3. Load Diffusion Model（`UNETLoader`）

- **作用**：只加载扩散/去噪模型，也常被称作 UNet 或 DiT 加载器。
- **输入**：模型文件名与权重 dtype/精度选项。
- **输出**：`MODEL`。
- **典型接法**：与 Load CLIP、Load VAE 组合，用于 Flux、视频模型等分体权重。
- **常见坑**：它不输出 CLIP 和 VAE；量化格式、精度与硬件不兼容会在加载或采样时失败。

### 4. Load CLIP（`CLIPLoader`）

- **作用**：加载一个文本编码器组件。
- **输入**：CLIP/文本编码器文件、模型类型和设备选项（具体以版本为准）。
- **输出**：`CLIP`。
- **典型接法**：`Load CLIP → 模型专用 Text Encode → CONDITIONING`。
- **常见坑**：这里的 CLIP 是泛称，实际可能是 CLIP、T5 等组合；必须按模型模板选择类型。

### 5. Load CLIP (Dual)（`DualCLIPLoader`）

- **作用**：组合加载两个文本编码器。
- **输入**：`clip_name1`、`clip_name2` 和 `type`。
- **输出**：一个组合后的 `CLIP`。
- **典型接法**：SDXL、SD3、Flux 等需要多文本编码器的分体工作流。
- **常见坑**：两个文件的顺序和 `type` 不是随意的；按官方模板填写。

### 6. Load CLIP (Triple) / Load CLIP (Quadruple)

- **作用**：组合加载三个或四个文本编码器，供特定新模型使用。
- **输入**：多个 encoder 文件和模型类型。
- **输出**：组合 `CLIP`。
- **适用**：只有模型官方工作流明确要求时使用。
- **常见坑**：文本编码器总大小可能很大；错一个组件就可能出现 shape mismatch 或编码错误。

### 7. Load VAE（`VAELoader`）

- **作用**：加载独立 VAE，在 `IMAGE` 与 `LATENT` 间转换。
- **输入**：`vae_name`，通常来自 `models/vae/`。
- **输出**：`VAE`。
- **典型接法**：分体模型；或覆盖 checkpoint 内置 VAE。
- **常见坑**：VAE 与模型不匹配可能导致颜色异常、黑图、通道/shape 报错。

### 8. Load LoRA (Model and CLIP)（`LoraLoader`）

- **作用**：同时把 LoRA 应用到 `MODEL` 和 `CLIP`。
- **输入**：原始 MODEL、CLIP、`lora_name`、`strength_model`、`strength_clip`。
- **输出**：修改后的 `MODEL` 和 `CLIP`。
- **典型接法**：`Checkpoint → LoRA → KSampler/Text Encode`；多个 LoRA 可串联。
- **常见坑**：基础架构必须兼容；应把两个修改后的输出都接到后续；强度过高会互相干扰。

### 9. Load LoRA（`LoraLoaderModelOnly`）

- **作用**：只修改扩散 MODEL，不修改文本编码器。
- **输入**：MODEL、LoRA 文件和 `strength_model`。
- **输出**：修改后的 `MODEL`。
- **适用**：LoRA 本身只包含模型侧权重，或工作流明确要求 model-only。
- **常见坑**：不要因为节点名字更短就默认选择它；先看 LoRA 说明。

### 10. Load ControlNet Model（`ControlNetLoader`）

- **作用**：从 `models/controlnet/` 加载 ControlNet 权重。
- **输入**：`control_net_name`。
- **输出**：`CONTROL_NET`。
- **典型接法**：输出交给 Apply ControlNet，同时提供匹配的边缘/深度/姿态控制图。
- **常见坑**：ControlNet 必须匹配基础模型系列和控制图类型。

### 11. Load ControlNet Model (diff)（`DiffControlNetLoader`）

- **作用**：加载差分形式的 ControlNet，并结合基础 MODEL 恢复可用控制模型。
- **输入**：CONTROL_NET 文件和兼容的 MODEL。
- **输出**：`CONTROL_NET`。
- **适用**：模型说明明确写明 diff/difference ControlNet。
- **常见坑**：普通 ControlNet 不需要它；基础模型不对会导致结果异常或加载失败。

### 12. Load Upscale Model（`UpscaleModelLoader`）

- **作用**：加载 ESRGAN/RealESRGAN 等像素超分模型。
- **输入**：`model_name`，通常来自 `models/upscale_models/`。
- **输出**：`UPSCALE_MODEL`。
- **典型接法**：接 `Upscale Image (using Model)`。
- **常见坑**：超分倍率和训练用途由模型决定；人像、动漫和通用模型效果不同。

### 13. Load CLIP Vision（`CLIPVisionLoader`）

- **作用**：加载用于理解参考图的视觉编码器。
- **输入**：`clip_name`，通常来自 `models/clip_vision/`。
- **输出**：`CLIP_VISION`。
- **典型接法**：接 CLIP Vision Encode，再用于 unCLIP、风格或模型专用参考图条件。
- **常见坑**：它不是文本 CLIP，不能接普通 CLIP Text Encode。

### 14. Load Style Model（`StyleModelLoader`）

- **作用**：加载与 CLIP Vision 特征配合的风格模型。
- **输入**：风格模型文件。
- **输出**：`STYLE_MODEL`。
- **典型接法**：与 CLIP Vision Encode 一起送入 Apply Style Model。
- **常见坑**：这是特定风格条件体系，不等同于 LoRA；组件必须配套。

### 15. Load Hypernetwork（`HypernetworkLoader`）

- **作用**：把旧式 Hypernetwork 补丁应用到 MODEL。
- **输入**：MODEL、hypernetwork 文件、strength。
- **输出**：修改后的 `MODEL`。
- **适用**：兼容旧模型/旧工作流。
- **常见坑**：当前生态中远少于 LoRA；不要把 LoRA 文件交给它。

## 二、提示词与条件节点

### 16. CLIP Text Encode (Prompt)（`CLIPTextEncode`）

- **作用**：把文本转成 `CONDITIONING`，让模型能使用提示词。
- **输入**：`text` 和 `clip`。
- **输出**：`CONDITIONING`。
- **典型接法**：两个实例分别接 KSampler 的 positive 和 negative。
- **常见坑**：提示词语法取决于模型；CLIP 与模型不匹配时可能编码失败或效果差。

### 17. CLIP Set Last Layer（`CLIPSetLastLayer`）

- **作用**：设置 CLIP 在倒数第几层停止，俗称 clip skip。
- **输入**：CLIP、`stop_at_clip_layer`；`-1` 通常表示最后一层。
- **输出**：修改设置后的 `CLIP`。
- **适用**：部分 SD1.x 动漫模型明确推荐 clip skip 2 等设置。
- **常见坑**：不是通用质量增强；模型没要求时保持默认。

### 18. Conditioning (Combine)（`ConditioningCombine`）

- **作用**：把两组 conditioning 并列合并，让采样过程同时使用它们。
- **输入**：`conditioning_1`、`conditioning_2`。
- **输出**：合并后的 `CONDITIONING`。
- **适用**：组合两个独立条件分支或区域条件。
- **常见坑**：Combine 不是文本字符串拼接，也不等同于加权平均。

### 19. Conditioning (Average)（`ConditioningAverage`）

- **作用**：按权重混合两组 conditioning。
- **输入**：`conditioning_to`、`conditioning_from`、`conditioning_to_strength`。
- **输出**：混合条件。
- **适用**：在两种概念/提示间做连续插值。
- **常见坑**：权重语义要看端口方向；先测试 0、0.5、1 三个点。

### 20. Conditioning (Concat)（`ConditioningConcat`）

- **作用**：在 token/条件表示层面串接两组 conditioning。
- **输入**：两组 `CONDITIONING`。
- **输出**：串接条件。
- **适用**：需要保持两段编码结构的高级提示流程。
- **常见坑**：它和 Combine、Average 的数学含义不同，不能凭名字互换。

### 21. Conditioning (Multiply)（`ConditioningMultiply`）

- **作用**：按倍数缩放 conditioning 的强度表示。
- **输入**：CONDITIONING 和 multiplier。
- **输出**：缩放后的条件。
- **适用**：高级条件实验。
- **常见坑**：不等同于 CFG；过大的乘数容易破坏结果。

### 22. Conditioning (Set Area)（`ConditioningSetArea`）

- **作用**：把条件限制在 latent 中的矩形区域。
- **输入**：CONDITIONING、width、height、x、y、strength。
- **输出**：带区域元数据的 conditioning。
- **适用**：让不同提示负责画面不同区域。
- **常见坑**：部分坐标/尺寸按 latent 单位或节点定义处理；优先用百分比版本避免换分辨率后错位。

### 23. Conditioning (Set Area with Percentage)（`ConditioningSetAreaPercentage`）

- **作用**：用相对比例设置条件作用矩形。
- **输入**：宽高、x/y 的百分比以及 strength。
- **输出**：区域 conditioning。
- **优点**：改变最终分辨率时区域相对位置更稳定。
- **常见坑**：多个区域重叠时条件会共同作用，需控制强度。

### 24. Conditioning (Set Area Strength)（`ConditioningSetAreaStrength`）

- **作用**：修改已有区域条件的强度。
- **输入**：CONDITIONING、strength。
- **输出**：更新后的 conditioning。
- **适用**：先定义区域，再统一调强弱。
- **常见坑**：只有输入条件本身带区域信息时才有明确意义。

### 25. Conditioning (Set Mask)（`ConditioningSetMask`）

- **作用**：让 conditioning 只在遮罩区域按指定强度生效。
- **输入**：CONDITIONING、MASK、strength、mask bounds 行为。
- **输出**：带遮罩的 conditioning。
- **适用**：非矩形局部提示或区域生成。
- **常见坑**：先预览 MASK；遮罩尺寸、批次和黑白方向错误会导致条件作用错位。

### 26. Conditioning Zero Out（`ConditioningZeroOut`）

- **作用**：保留条件结构和元数据，但把条件向量归零。
- **输入/输出**：CONDITIONING → CONDITIONING。
- **适用**：高级 CFG、区域或模型实验，需要“同形状空条件”时使用。
- **常见坑**：它不等同于简单空字符串提示词，两者编码结果可能不同。

### 27. ConditioningSetTimestepRange

- **作用**：限制一组条件只在采样时间轴的某个百分比区间生效。
- **输入**：CONDITIONING、`start`、`end`。
- **输出**：带时间范围的 conditioning。
- **适用**：早期控制构图、后期控制细节等分阶段提示。
- **常见坑**：这是采样进度，不是视频时间，也不是图片空间位置。

### 28. CLIP Vision Encode（`CLIPVisionEncode`）

- **作用**：把参考 IMAGE 编码成视觉 embedding。
- **输入**：`clip_vision`、`image` 和裁剪方式。
- **输出**：`CLIP_VISION_OUTPUT`。
- **典型接法**：送入 unCLIPConditioning、Apply Style Model 或模型专用节点。
- **常见坑**：裁剪会改变参考构图；视觉编码器必须与下游体系兼容。

### 29. Apply Style Model（`StyleModelApply`）

- **作用**：用 STYLE_MODEL 和视觉特征修改 conditioning。
- **输入**：conditioning、style model、CLIP vision output。
- **输出**：新的 `CONDITIONING`。
- **适用**：参考图风格条件工作流。
- **常见坑**：它不是直接像素风格迁移，结果仍由扩散模型生成。

### 30. unCLIPConditioning（`unCLIPConditioning`）

- **作用**：把 CLIP Vision 输出加入 conditioning，支持 unCLIP 图像条件。
- **输入**：conditioning、CLIP vision output、strength、noise augmentation。
- **输出**：增强的 conditioning。
- **常见坑**：只对兼容 unCLIP 的 checkpoint/工作流有效；noise augmentation 越高参考越不精确。

### 31. Apply ControlNet（`ControlNetApplyAdvanced`）

- **作用**：把控制图和 ControlNet 同时写入正向、负向条件。
- **输入**：positive、negative、control_net、image、strength、start/end percent，可选 VAE。
- **输出**：修改后的 positive 和 negative。
- **典型接法**：两个输出替换原先直接进入 KSampler 的条件线。
- **常见坑**：控制图类型、ControlNet 权重和基础模型必须匹配；start/end 表示采样阶段。

### 32. Apply ControlNet（`ControlNetApply`，已弃用）

- **作用**：旧版只处理一组 conditioning 的 ControlNet 应用节点。
- **适用**：保持旧工作流兼容。
- **迁移**：新工作流用 Advanced 版本同时处理正/负条件。
- **常见坑**：不要因为节点名更短就在新链中优先选它。

### 33. InpaintModelConditioning

- **作用**：为局部重绘模型同时准备正向、负向条件和 latent。
- **输入**：positive、negative、VAE、pixels、mask、noise_mask 开关。
- **输出**：positive、negative、LATENT。
- **典型接法**：输出三项直接接采样器对应端口。
- **常见坑**：专用 inpaint checkpoint 可能依赖它提供的额外通道；遮罩方向先预览。

## 三、采样节点

### 34. KSampler（`KSampler`）

- **作用**：把模型、正负条件和初始 latent 组合起来，执行完整去噪采样。
- **必需输入**：MODEL、positive、negative、latent_image。
- **参数**：seed、steps、cfg、sampler_name、scheduler、denoise。
- **输出**：采样后的 `LATENT`，仍需 VAE Decode。
- **常见坑**：参数推荐依模型而变；denoise=1 适合文生图，图生图通常小于 1。

### 35. KSampler (Advanced)（`KSamplerAdvanced`）

- **作用**：暴露噪声开关、起止步、剩余噪声等高级控制，可把一次采样拆成多段。
- **输入**：与普通 KSampler 相似，另有 `add_noise`、`noise_seed`、`start_at_step`、`end_at_step`、`return_with_leftover_noise`。
- **输出**：LATENT。
- **适用**：基础/Refiner 分段、恢复采样、两阶段 latent 工作流。
- **常见坑**：第二段是否加噪、第一段是否留下噪声必须成对设置；不是“更高级所以质量更好”。

### 36. RandomNoise / DisableNoise / AddNoise

- **作用**：在自定义采样链中创建随机噪声、创建禁用噪声对象，或显式把噪声加到 latent。
- **输入/输出**：seed 或 latent/sigmas 等 → `NOISE`/`LATENT`。
- **适用**：SamplerCustom 系列，不是普通 KSampler 的必需节点。
- **常见坑**：NOISE 与 LATENT 类型不同；重复加噪会改变预期采样起点。

### 37. KSamplerSelect

- **作用**：只选择采样算法并输出 `SAMPLER` 对象。
- **输入**：sampler_name 下拉。
- **输出**：`SAMPLER`。
- **典型接法**：接 SamplerCustom/Advanced。
- **常见坑**：它本身不执行采样，也不接受 MODEL。

### 38. BasicScheduler / KarrasScheduler / ExponentialScheduler

- **作用**：根据 MODEL、steps、denoise 等生成一串 `SIGMAS` 噪声水平。
- **输出**：`SIGMAS`。
- **典型接法**：接 SamplerCustom。
- **区别**：不同 scheduler 的 sigma 分布不同，不能只按名称判断质量。
- **常见坑**：模型专用 scheduler 优先于通用选择；SIGMAS 不是普通数字列表端口。

### 39. Basic Guider / CFG Guider / Dual CFG Guider

- **作用**：把 MODEL 与一组或多组 conditioning 封装成采样 guider。
- **输入**：MODEL、positive/negative conditioning、cfg 等。
- **输出**：`GUIDER`。
- **典型接法**：接 SamplerCustomAdvanced。
- **常见坑**：Basic Guider 与 CFG Guider 的条件语义不同；模型专用 guidance 不应强套传统 CFG。

### 40. SamplerCustom

- **作用**：用显式 MODEL、噪声、guider/sampler、sigmas 和 latent 执行模块化采样。
- **输出**：通常包含带噪输出、去噪输出等 latent 结果。
- **适用**：需要精确控制噪声和时间表的高级工作流。
- **常见坑**：其连接结构与 KSampler 不同；不要漏掉 VAE 解码。

### 41. SamplerCustomAdvanced

- **作用**：更彻底拆分采样器、guider、sigmas、noise 和 latent。
- **优势**：方便复用噪声、切分 sigmas、组合自定义 guider。
- **适用**：模型官方高级模板、研究和分段采样。
- **常见坑**：先能解释每个对象再修改；随意替换一项可能破坏模型要求。

## 四、潜空间与 VAE 节点

### 42. Empty Latent Image（`EmptyLatentImage`）

- **作用**：创建指定宽、高和批量的空图像 latent。
- **参数**：width、height、batch_size。
- **输出**：`LATENT`。
- **典型接法**：文生图的 KSampler `latent_image`。
- **常见坑**：模型系列可能有专用 Empty Latent；普通版本并不适合所有视频/新架构。

### 43. VAE Encode（`VAEEncode`）

- **作用**：把 IMAGE 编码到 LATENT。
- **输入**：pixels、vae。
- **输出**：`LATENT`。
- **典型接法**：图生图。
- **常见坑**：输入尺寸可能按 VAE 规则裁到可编码倍数；VAE 必须匹配模型。

### 44. VAE Decode（`VAEDecode`）

- **作用**：把 LATENT 解码为 IMAGE。
- **输入**：samples、vae。
- **输出**：`IMAGE`。
- **典型接法**：KSampler → VAE Decode → Preview/Save Image。
- **常见坑**：直接保存 LATENT 不会得到普通图片；黑图要检查 VAE 和精度。

### 45. VAE Encode (Tiled)（`VAEEncodeTiled`）

- **作用**：分块编码大图，降低峰值显存。
- **输入**：pixels、vae、tile size/overlap/temporal size 等版本相关参数。
- **输出**：LATENT。
- **代价**：速度更慢，tile 或 overlap 不合适可能产生接缝。
- **适用**：普通 VAE Encode 因大图 OOM 时。

### 46. VAE Decode (Tiled)（`VAEDecodeTiled`）

- **作用**：分块把大 latent 解码为图像，降低峰值显存。
- **输入**：samples、vae 和分块参数。
- **输出**：IMAGE。
- **适用**：高分辨率解码 OOM。
- **常见坑**：它不能降低采样阶段的所有显存，只解决 VAE 解码这一段。

### 47. VAE Encode (for Inpainting)（`VAEEncodeForInpaint`）

- **作用**：按 mask 准备局部重绘 latent，并附带 noise mask。
- **输入**：pixels、vae、mask、grow_mask_by。
- **输出**：带遮罩信息的 LATENT。
- **典型接法**：输出接 KSampler；白色遮罩区域通常允许重绘。
- **常见坑**：遮罩边缘太硬会有接缝；先预览，再适度扩张/羽化。

### 48. Set Latent Noise Mask（`SetLatentNoiseMask`）

- **作用**：把 MASK 附加到已有 LATENT，告诉采样器哪些区域可加噪/修改。
- **输入**：samples、mask。
- **输出**：带 noise_mask 的 LATENT。
- **适用**：自定义局部采样链。
- **常见坑**：它不负责 VAE 编码，也不会自动羽化或反相遮罩。

### 49. Upscale Latent（`LatentUpscale`）

- **作用**：把 latent 缩放到明确宽高。
- **输入**：samples、upscale_method、width、height、crop。
- **输出**：LATENT。
- **典型接法**：第一阶段采样 → latent upscale → 第二阶段低 denoise 采样。
- **常见坑**：只缩放 latent 不会自动增加真实细节，通常还需二次采样。

### 50. Upscale Latent By（`LatentUpscaleBy`）

- **作用**：按倍率缩放 latent。
- **输入**：samples、upscale_method、scale_by。
- **输出**：LATENT。
- **优点**：比手算目标宽高方便。
- **常见坑**：倍率 2 意味着像素约 4 倍，第二次采样显存会显著上升。

### 51. Crop Latent / Rotate Latent / Flip Latent

- **作用**：在潜空间中裁剪、旋转或翻转。
- **输入/输出**：LATENT → LATENT。
- **适用**：无需先解码的几何变换或潜空间实验。
- **常见坑**：latent 分辨率与像素分辨率有缩放关系，裁剪坐标应按节点定义理解。

### 52. Latent Composite（`LatentComposite`）

- **作用**：把一个 latent 贴到另一个 latent 的指定位置。
- **输入**：destination、source、x、y、feather。
- **输出**：合成 LATENT。
- **适用**：潜空间拼接或区域组合。
- **常见坑**：源和目标的批次、通道/模型 latent 格式必须兼容。

### 53. Latent Composite Masked（`LatentCompositeMasked`）

- **作用**：用 MASK 控制 source latent 合成到 destination 的区域。
- **输入**：destination、source、可选 mask 和位置/缩放设置。
- **输出**：LATENT。
- **常见坑**：先验证遮罩方向和尺寸；不同模型的专用 latent 不一定可互相合成。

### 54. Latent Blend（`LatentBlend`）

- **作用**：按比例混合两个 latent。
- **输入**：samples1、samples2、blend factor。
- **输出**：LATENT。
- **适用**：潜空间插值实验。
- **常见坑**：几何不对齐的 latent 混合会产生不可预测内容，不等同于图片透明度混合。

### 55. Get Latent From Batch（`LatentFromBatch`）

- **作用**：从 latent batch 中按索引取一段。
- **输入**：samples、batch_index、length。
- **输出**：LATENT。
- **适用**：一次生成多张后只继续处理其中一张/几张。
- **常见坑**：索引从 0 开始；越界会报错或得到空结果。

### 56. Repeat Latent Batch（`RepeatLatentBatch`）

- **作用**：把 latent 批次重复指定次数。
- **输入**：samples、amount。
- **输出**：更大批次 LATENT。
- **适用**：让同一初始 latent 配合批量条件。
- **常见坑**：批次增大直接增加显存；重复数据不代表自动得到不同 seed。

### 57. Batch Latents / Rebatch Latents

- **作用**：把多个 latent 合成批次，或重新切分批次大小。
- **输入/输出**：一个或多个 LATENT → LATENT/列表。
- **适用**：批处理、列表工作流和视频分段。
- **常见坑**：合并项需具有兼容形状和附加元数据。

### 58. Load Latent / Save Latent

- **作用**：把内部 latent 保存到文件，或从文件恢复。
- **输入/输出**：LATENT ↔ latent 文件。
- **适用**：长工作流断点、研究和跨工作流复用中间结果。
- **常见坑**：latent 依赖模型/VAE及格式，不能当通用图片分享；只加载可信文件。

## 五、图像输入、输出与变换节点

### 59. Load Image（`LoadImage`）

- **作用**：从 ComfyUI 输入目录/上传控件读取图片。
- **输入**：image 文件选择。
- **输出**：`IMAGE` 和 `MASK`；MASK 通常来自 alpha 通道或遮罩编辑器。
- **典型接法**：IMAGE → VAE Encode、预处理器或图像变换；MASK → inpaint。
- **常见坑**：普通无透明通道图片的 MASK 往往是空/全黑；EXIF 方向和色彩配置可能影响显示。

### 60. Load Image (as Mask)（`LoadImageMask`）

- **作用**：把图片的指定颜色通道读取成 MASK。
- **输入**：image 和 channel（red/green/blue/alpha）。
- **输出**：`MASK`。
- **适用**：使用外部灰度/alpha 遮罩。
- **常见坑**：选错通道会得到全黑/全白；先接 Preview Mask。

### 61. Load Image (from Outputs)（`LoadImageOutput`）

- **作用**：从 ComfyUI 输出目录再次读取已生成图片。
- **输出**：IMAGE 和 MASK。
- **适用**：把上一轮结果作为新工作流输入。
- **常见坑**：依赖本机输出文件；分享工作流时其他人可能没有同一路径文件。

### 62. Preview Image（`PreviewImage`）

- **作用**：在界面中预览 IMAGE，使用临时输出，不作为正式文件命名流程。
- **输入**：images。
- **输出**：面向 UI 的图像结果。
- **适用**：调试中间结果、对比多个分支。
- **常见坑**：临时文件可能被清理；最终作品用 Save Image。

### 63. Save Image（`SaveImage`）

- **作用**：把 IMAGE 写入 ComfyUI `output/`，并通常嵌入工作流元数据。
- **输入**：images、filename_prefix；prompt/extra_pnginfo 是隐藏输入。
- **输出**：供 UI 展示的保存结果。
- **典型用法**：prefix 可包含子目录或格式化占位符，具体语法以节点帮助为准。
- **常见坑**：同名前缀会自动编号而不是覆盖；平台压缩图片后可能丢失工作流元数据。

### 64. Empty Image（`EmptyImage`）

- **作用**：创建纯色 IMAGE 画布。
- **输入**：width、height、batch_size、color。
- **输出**：IMAGE。
- **适用**：合成底图、测试遮罩/布局、创建占位图。
- **常见坑**：这是像素图，不是 Empty Latent Image，不能直接作为普通 KSampler latent。

### 65. Upscale Image（`ImageScale`）

- **作用**：用传统插值把 IMAGE 缩放到指定宽高。
- **参数**：upscale_method、width、height、crop。
- **输出**：IMAGE。
- **适用**：尺寸对齐和普通缩放。
- **常见坑**：不会像超分模型一样创造细节；center crop 可能裁掉边缘。

### 66. Upscale Image By（`ImageScaleBy`）

- **作用**：按倍率传统插值缩放 IMAGE。
- **输入**：image、upscale_method、scale_by。
- **输出**：IMAGE。
- **优点**：无需计算目标尺寸。
- **常见坑**：倍率改变后尺寸可能不满足后续模型的步长要求，需要再对齐。

### 67. Scale Image to Total Pixels（`ImageScaleToTotalPixels`）

- **作用**：保持比例，把图片缩放到目标总像素规模。
- **输入**：IMAGE、upscale_method、megapixels。
- **输出**：IMAGE。
- **适用**：不同长宽比图片统一计算量。
- **常见坑**：总像素相同不代表宽高相同；批处理下游仍需支持不同尺寸。

### 68. Upscale Image (using Model)（`ImageUpscaleWithModel`）

- **作用**：使用 `UPSCALE_MODEL` 对 IMAGE 做神经网络超分。
- **输入**：upscale_model、image。
- **输出**：放大后的 IMAGE。
- **典型接法**：Load Upscale Model → 本节点。
- **常见坑**：输出倍率由模型决定；可能产生假纹理、光晕或过度锐化。

### 69. Crop Image（`ImageCrop`）

- **作用**：按 width、height、x、y 裁剪 IMAGE。
- **输出**：IMAGE。
- **适用**：明确坐标的像素裁剪。
- **常见坑**：坐标越界时结果按实现裁切；批次中所有图通常使用同一裁剪参数。

### 70. Stitch Images（`ImageStitch`）

- **作用**：按方向把图像拼接起来。
- **输入**：两个或多个 IMAGE 以及方向/匹配方式。
- **输出**：IMAGE。
- **适用**：对比图、长图和分块结果拼接。
- **常见坑**：非拼接方向的尺寸需兼容；它不自动消除接缝。

### 71. Pad Image for Outpainting（`ImagePadForOutpaint`）

- **作用**：向图片四周增加画布，并产生对应 MASK 供扩图重绘。
- **输入**：image、left/top/right/bottom、feathering。
- **输出**：补边 IMAGE 和 MASK。
- **典型接法**：两项一起送入 inpaint 编码/条件节点。
- **常见坑**：feathering 过大可能侵入原图；提示词要描述扩展后的完整场景。

### 72. Invert Image Colors（`ImageInvert`）

- **作用**：把 IMAGE 颜色值反相。
- **输入/输出**：IMAGE → IMAGE。
- **适用**：负片效果或某些控制图预处理。
- **常见坑**：它处理彩色 IMAGE，不是 Invert Mask。

### 73. Blend Images（`ImageBlend`）

- **作用**：按 blend factor 和模式混合两个 IMAGE。
- **输出**：IMAGE。
- **适用**：像素级过渡、叠加和后处理。
- **常见坑**：两图尺寸/批次需兼容；这是像素混合，不是 latent/conditioning 插值。

### 74. Image Composite Masked（`ImageCompositeMasked`）

- **作用**：把 source IMAGE 按 MASK 和位置合成到 destination IMAGE。
- **输入**：destination、source、x、y、resize_source、可选 mask。
- **输出**：IMAGE。
- **适用**：贴图、局部替换和分层合成。
- **常见坑**：source/destination 语义容易接反；MASK 的白色通常表示 source 参与合成。

### 75. Blur Image（`ImageBlur`）

- **作用**：对 IMAGE 做模糊。
- **输入**：image、blur_radius、sigma 等版本相关参数。
- **输出**：IMAGE。
- **适用**：背景柔化、预处理、降低高频细节。
- **常见坑**：半径按像素尺度理解；高分辨率图需要不同数值。

### 76. Sharpen Image（`ImageSharpen`）

- **作用**：对 IMAGE 锐化，增强局部边缘对比。
- **输入**：image、radius、sigma、alpha 等。
- **输出**：IMAGE。
- **常见坑**：过强会放大噪点和产生白边；在最终尺寸上判断效果。

### 77. Quantize Image（`ImageQuantize`）

- **作用**：减少颜色数量并选择抖动方式。
- **输入**：image、colors、dither。
- **输出**：IMAGE。
- **适用**：像素风、调色板压缩或特殊效果。
- **常见坑**：它会有意损失颜色，不是图片文件压缩质量设置。

### 78. Batch Images（`ImageBatch`，已弃用）

- **作用**：把两组兼容 IMAGE 合并为批次。
- **替代**：新工作流使用当前 Batch Images / Rebatch Images 节点。
- **常见坑**：图片尺寸不一致时不能直接组成普通 batch。

### 79. Get Image from Batch / Repeat Image Batch / Rebatch Images

- **作用**：从批次取图、重复批次或重新分批。
- **输入/输出**：IMAGE 批次或列表 → IMAGE 批次/列表。
- **适用**：批量生成后的分支处理。
- **常见坑**：batch 与“队列运行次数”不同；扩大 batch 会增加显存。

### 80. Make Image Grid

- **作用**：把一批图片排成网格对比图。
- **输入**：IMAGE 列表/批次和行列配置。
- **输出**：单张或批次 IMAGE。
- **适用**：参数对比和联系表。
- **常见坑**：输入尺寸不一致时需要先统一；网格图不是原始单图替代品。

### 81. Split Image into List of Tiles / Merge List of Tiles to Image

- **作用**：把大图拆成 tile 列表，处理后再按布局合并。
- **参数**：tile 宽高、overlap、行列/布局信息等。
- **适用**：分块放大、滤镜或受显存限制的处理。
- **常见坑**：拆分与合并参数必须对应；无 overlap 或融合策略容易出现接缝。

### 82. Get Image Size

- **作用**：读取 IMAGE 的宽度、高度和批次等尺寸信息。
- **输入**：IMAGE。
- **输出**：INT 数值。
- **适用**：动态计算 resize、crop、比例或网格参数。
- **常见坑**：输出只是数字，不会改变图片。

## 六、遮罩节点

### 83. Convert Image to Mask（`ImageToMask`）

- **作用**：从 IMAGE 的指定通道提取 MASK。
- **输入**：image、channel。
- **输出**：MASK。
- **适用**：把灰度图或某颜色通道转成遮罩。
- **常见坑**：彩色图不同通道结果不同；先预览。

### 84. Convert Image Color to Mask（`ImageColorToMask`）

- **作用**：按指定颜色从 IMAGE 创建 MASK。
- **输入**：image、color。
- **输出**：MASK。
- **适用**：从纯色分区图/语义图提取区域。
- **常见坑**：JPEG 压缩会使颜色不再完全一致；需要容差时使用支持阈值的节点。

### 85. Convert Mask to Image（`MaskToImage`）

- **作用**：把单通道 MASK 转成可预览/保存的 IMAGE。
- **输入/输出**：MASK → IMAGE。
- **适用**：调试遮罩。
- **常见坑**：转换后再参与 mask 运算可能需要转回来；不要混淆端口类型。

### 86. Create Solid Mask（`SolidMask`）

- **作用**：创建指定宽高和数值的纯色 MASK。
- **参数**：value、width、height。
- **输出**：MASK。
- **适用**：全保留/全作用测试、遮罩合成底板。
- **常见坑**：0 与 1 的语义由下游决定；纯白并不永远代表“保留”。

### 87. Invert Mask（`InvertMask`）

- **作用**：执行 `1 - mask`，交换黑白区域。
- **输入/输出**：MASK → MASK。
- **适用**：修正遮罩作用方向。
- **常见坑**：不要用 Image Invert 替代；先 Preview Mask 确认。

### 88. Crop Mask（`CropMask`）

- **作用**：按矩形坐标裁剪 MASK。
- **输入**：mask、width、height、x、y。
- **输出**：MASK。
- **常见坑**：若同时裁图片，必须使用一致区域确保对齐。

### 89. Grow Mask（`GrowMask`）

- **作用**：膨胀或收缩遮罩边界。
- **输入**：mask、expand、tapered_corners 等。
- **输出**：MASK。
- **适用**：局部重绘时扩大上下文，或缩小作用区。
- **常见坑**：像素数应随分辨率调整；负值通常表示收缩。

### 90. Feather Mask（`FeatherMask`）

- **作用**：分别对遮罩四边做渐变羽化。
- **输出**：MASK。
- **适用**：减少合成/重绘硬接缝。
- **常见坑**：羽化太大会让原本应保留的区域也被影响。

### 91. Threshold Mask（`ThresholdMask`）

- **作用**：按阈值把软遮罩转为更明确的黑白遮罩。
- **输入**：mask、value。
- **输出**：MASK。
- **适用**：清理分割结果或建立硬边区域。
- **常见坑**：会丢掉半透明过渡；如需柔边，应在阈值后再 Feather。

### 92. Combine Masks / Mask Composite（`MaskComposite`）

- **作用**：用 add、subtract、multiply、and/or 等模式组合遮罩。
- **输入**：destination、source、位置和 operation。
- **输出**：MASK。
- **适用**：把多个物体区域组合、相减或求交集。
- **常见坑**：operation 的数学语义不同；用三块简单纯色遮罩先验证。

### 93. Batch Masks（`BatchMasksNode`）

- **作用**：把多个尺寸兼容的 MASK 组织成批次。
- **输入/输出**：MASK → MASK batch。
- **适用**：批量局部处理。
- **常见坑**：每张图的 mask 要与对应图片 batch 顺序一致。

### 94. Preview Mask

- **作用**：直接在界面查看 MASK，避免反复 Mask to Image。
- **输入**：MASK。
- **适用**：任何 inpaint、ControlNet 区域、图像合成前的检查。
- **常见坑**：预览看起来正确还要确认下游对白/黑的定义。

### 95. Split Image with Alpha / Join Image with Alpha

- **作用**：把 RGBA 图片拆成 RGB IMAGE + alpha MASK，或把 IMAGE 与 MASK 合成带 alpha 的图片。
- **输入/输出**：IMAGE ↔ IMAGE + MASK。
- **适用**：透明背景、图层和抠图流程。
- **常见坑**：alpha 与 inpaint mask 的“作用方向”可能相反，需要 Invert Mask。

### 96. Porter-Duff Image Composite

- **作用**：使用标准 Porter-Duff alpha 合成规则组合源图和目标图。
- **输入**：source/destination IMAGE 与对应 MASK、composite mode。
- **输出**：合成 IMAGE/MASK。
- **适用**：需要严格透明度语义的图层合成。
- **常见坑**：`source-over`、`destination-in` 等模式方向性很强，接反会得到透明或空结果。

## 七、基础辅助节点

### 97. Reroute（前端节点）

- **作用**：整理连线，不改变数据。
- **类型**：连接后继承相邻端口类型。
- **适用**：长距离连线、总线式布局。
- **常见坑**：未确定类型的 Reroute 不能随意分叉到不同类型。

### 98. Primitive / Int / Float / Text / Boolean

- **作用**：把固定参数作为可连线数据提供给其他节点。
- **输出**：INT、FLOAT、STRING、BOOLEAN 或动态适配类型。
- **适用**：一个参数控制多处、制作可复用子图/APP 输入。
- **常见坑**：整数和浮点并非所有端口都自动互转；用 Convert Number 时明确取整策略。

### 99. Seed

- **作用**：提供 seed 数值及运行后的随机/递增行为，方便统一管理随机性。
- **输出**：通常是 `INT` seed。
- **适用**：多个采样或噪声节点共享同一 seed。
- **常见坑**：连接同一 seed 不代表不同模型/采样器生成内容相同。

### 100. Resolution Selector

- **作用**：从常见分辨率或比例生成 width/height 数值。
- **输出**：INT 宽高。
- **适用**：把分辨率选择集中到一个节点。
- **常见坑**：预设分辨率未必适合当前模型；仍要遵循模型像素和步长要求。

### 101. Math Expression

- **作用**：根据输入变量计算数字表达式。
- **输出**：数值结果。
- **适用**：动态宽高、倍率、帧数和批次计算。
- **常见坑**：除零、负尺寸和非整数结果会让下游失败；涉及尺寸时明确取整并对齐倍数。

### 102. Preview as Text

- **作用**：把任意可显示数据转成文本预览，便于调试数值、路径或结构。
- **输入**：通用数据。
- **输出/界面**：文本显示。
- **常见坑**：预览不等于保存；大对象可能只显示摘要。
