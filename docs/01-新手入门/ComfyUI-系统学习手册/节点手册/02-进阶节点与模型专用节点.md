# 进阶节点与模型专用节点

这部分节点数量多、更新快，而且很多只对某一个模型家族有效。学习重点不是逐个背参数，而是识别它处于“加载 → 条件 → latent → 采样 → 解码/保存”的哪个位置。

## 1. 模块化采样体系

普通 KSampler 把多件事封装在一个节点中：

```text
MODEL + 正负条件 + seed + steps + sampler + scheduler + latent
                              ↓
                           KSampler
                              ↓
                            LATENT
```

自定义采样把它拆开：

```text
seed → RandomNoise ───────────────────────────┐
MODEL + conditions → CFG Guider ─────────────┤
sampler_name → KSamplerSelect ───────────────┤→ SamplerCustomAdvanced → LATENT
MODEL + steps → Basic/Karras Scheduler ──────┤
初始 latent ─────────────────────────────────┘
```

### Noise 节点

- `RandomNoise`：由 seed 定义噪声来源。
- `DisableNoise`：提供“不要新增噪声”的对象，常用于继续去噪。
- `AddNoise`：显式根据 sigmas 把噪声加入 latent。

### Sampler 节点

`KSamplerSelect`、`SamplerEulerAncestral`、`SamplerDPMPP_*`、`SamplerLCM` 等输出 `SAMPLER` 对象，不一定直接输出图片或 latent。它们定义“每一步怎么算”。

### Scheduler 节点

`BasicScheduler`、`KarrasScheduler`、`ExponentialScheduler`、`BetaSamplingScheduler`、`SDTurboScheduler`、`AlignYourStepsScheduler` 以及模型专用 scheduler 输出 `SIGMAS`。它们定义“在哪些噪声水平上走这些步”。

### Sigmas 工具

- `SplitSigmas` / `SplitSigmasDenoise`：把时间表拆成前后两段。
- `FlipSigmas`：反转 sigma 顺序，属于特殊实验。
- `SetFirstSigma`：修改第一个噪声水平。
- `ExtendIntermediateSigmas`：扩展中间区间。
- `SamplingPercentToSigma`：把百分比转换成模型对应 sigma。
- `ManualSigmas`：手动提供数列。

除非能解释每个 sigma 的目的，不要在模型官方模板外随意修改。

### Guider 节点

- `Basic Guider`：用一组 conditioning 引导。
- `CFG Guider`：传统正/负条件与 CFG。
- `Dual CFG Guider` / `Dual Model CFG Guider`：两组条件或双模型引导。
- `Video Linear CFG Guidance` / `Video Triangle CFG Guidance`：随视频帧/过程变化的 guidance。
- `CFG Override`：覆盖其他链路中的 CFG 设置。

Guider 输出给自定义采样器，不是普通 `CONDITIONING`。

## 2. Guidance 与实验采样

这一类节点通常接收并输出 MODEL，或输出 GUIDER：

- `CFGNorm`、`CFGZeroStar`、`RenormCFG`、`RescaleCFG`：改变 CFG 的归一化/重标定行为。
- `Normalized Attention Guidance`、`Self-Attention Guidance`：利用注意力修改引导。
- `PerturbedAttentionGuidance`、`Perp-Neg Guider`：特殊负向/扰动引导。
- `SkipLayerGuidance*`：跳过指定层以形成额外引导。
- `Tangential Damping CFG`、`Positive-Biased Guidance`：研究性 guidance 变体。

使用原则：

1. 先保存无补丁基线图。
2. 固定 seed 和所有其他参数。
3. 每次只接一个 guidance 补丁。
4. 对比质量、速度、显存和稳定性。

## 3. MODEL Patch 节点

MODEL patch 通常是：

```text
MODEL → Patch A → Patch B → KSampler
```

它们修改推理行为而不是权重文件本身；除非再用保存节点，否则不会覆盖磁盘模型。

### 通用性能/结构补丁

- `FreeU` / `FreeU_V2`：调整 UNet 跳连与骨干特征强度。
- `HyperTile`：分块注意力以尝试降低某些高分辨率开销。
- `TomePatchModel`：Token merging 速度/质量折中。
- `PatchModelAddDownscale (Kohya Deep Shrink)`：在部分层缩放特征，常用于高分辨率实验。
- `TorchCompileModel`：用 PyTorch 编译模型；首轮编译慢，环境兼容性要求高。
- `ModelAttentionBackend`：选择注意力实现；硬件/依赖不支持时会失败。
- `EasyCache` / `LazyCache` / `Flux KV Cache`：缓存模型计算，适合特定工作流和重复结构。

### 采样配置补丁

- `ModelSamplingDiscrete`、`ModelSamplingContinuousEDM/V`：改变模型采样参数化。
- `ModelSamplingSD3`、`ModelSamplingFlux`、`ModelSamplingLTXV`、`ModelSamplingMiniMaxH3`、`ModelSamplingStableCascade`：模型家族专用采样配置。
- `ModelNoiseScale`、`Epsilon Scaling`、`ScaleROPE`：修改噪声或位置编码行为。

这些不是“切换成另一个模型”的节点。错误的 patch 可能不立刻报错，却会明显破坏结果。

### Context Windows

`Context Windows (Manual)`、`LTXV Context Windows`、`Wan Context Windows` 把长时序/大上下文推理切成窗口。重点参数通常是窗口长度、重叠和融合方法。

风险：窗口太小会破坏长期一致性，重叠太小产生接缝，太大则显存/耗时上升。

## 4. 模型合并与权重保存

### 合并

- `ModelMergeSimple`：按比例混合两模型。
- `ModelMergeBlocks`：按网络区块设置不同权重。
- `ModelMergeAdd` / `ModelMergeSubtract`：做权重加减。
- `CLIPMerge*`：对文本编码器做对应合并。
- `ModelMergeSD1/SDXL/Flux1/WAN2_1/...`：按模型特定结构暴露区块比例。

### 保存

- `Save Checkpoint`：保存 MODEL，可组合 CLIP/VAE。
- `ModelSave`、`CLIPSave`、`VAESave`：保存分体组件。
- `Save LoRA Weights`：保存 LoRA 权重。
- `ImageOnlyCheckpointSave`：保存图像模型相关 checkpoint。

注意：

- 合并通常需要大量 RAM/VRAM 和磁盘临时空间。
- 输入模型架构必须一致或由专用合并节点明确支持。
- 保存前核对输出目录和文件名，避免产生大量权重。
- 模型许可可能禁止合并、再分发或商用；技术上能保存不代表法律上能发布。

## 5. 模型专用 Conditioning 的识别方法

看到以下名字，应立即寻找对应官方模板：

| 前缀/类别 | 典型任务 | 常见专用信息 |
|---|---|---|
| `CLIPTextEncodeSDXL/SD3/Flux` | 图像生成 | 多文本编码器、尺寸、guidance |
| `Wan*ToVideo` | Wan 视频 | 首尾帧、控制视频、相机、音频、轨迹 |
| `Hunyuan*` | 图像/视频/3D | 模型专用 latent 和条件 |
| `LTXV*` | LTX-Video | guide、时长、音视频 latent、context |
| `MiniMax H3*` | MiniMax H3 音视频 | AV latent、参考图/视频、采样 patch |
| `Qwen Image*` | Qwen 图像/编辑 | 专用文本编码和多图条件 |
| `StableCascade*` | Stable Cascade | Stage C/B 两阶段 latent/conditioning |
| `Trellis2*` / `TripoSplat*` | 3D | 结构、纹理、多阶段解码 |
| `ACE Step*` | 音乐/音频 | 音频 latent、歌词/文本条件、时长 |

### 为什么不能用通用节点替代

专用节点常常同时完成多项工作：

- 把图片编码后放进 conditioning 元数据。
- 调整到模型要求的宽高/帧数。
- 构造额外 latent 通道。
- 添加模型期望的 guidance 数值。
- 处理首帧、尾帧、参考帧和遮罩。

即使输出类型仍叫 `CONDITIONING` 或 `LATENT`，内部结构也可能不同。

## 6. 模型专用 Empty Latent

当前内置节点包含多种空 latent，例如：

- `EmptySD3LatentImage`
- `Empty Flux 2 Latent`
- `EmptyMochiLatentVideo`
- `EmptyLTXVLatentVideo`
- `Empty HunyuanVideo 1.0/1.5 Latent`
- `Empty MiniMax H3 AV Latent`
- `Empty Ace Step Latent Audio`
- `EmptyTrellis2LatentStructure`

它们不只是不同标题；通道数、缩放系数、帧维度、音视频结构或附加元数据可能不同。模型模板用了专用 Empty Latent 时，不要换成普通 `Empty Latent Image`。

## 7. 视频节点

### 通用 I/O

- `Load Video`：读取视频，可能输出 VIDEO 或可拆分媒体对象。
- `Get Video Components`：取出帧、音频、帧率等组件。
- `Create Video`：把图片帧、帧率和可选音频组成视频。
- `Save Video` / `Save WEBM`：编码并保存。
- `Trim Video`：按时间或帧裁剪。
- `Sample Video Frame`：抽取指定帧。

### 插帧

`Load Frame Interpolation Model → Run Frame Interpolation Model` 在相邻帧间生成过渡帧。它提高帧率/顺滑度，不会自动修复主体一致性。快速运动、遮挡和镜头切换处容易产生重影。

### 视频 latent 与条件

视频模型常要求帧数满足 `k × n + 1` 等约束，具体数值依模型。帧数、宽高、batch 和上下文窗口共同决定显存，先用官方模板的最小时长验证。

### 音视频同步

带音频条件的节点可能按采样率、时长和帧率对齐。修改任一项后，检查输出时长、音轨是否被截断，以及模型是否要求固定片段长度。

## 8. 音频节点

### I/O 与基础处理

- `Load Audio` / `Record Audio`：读取或录制 AUDIO。
- `Preview Audio` / `Save Audio (Advanced)`：预览或保存。
- `Trim Audio Duration`：裁剪时长。
- `Adjust Audio Volume`：调整音量。
- `Audio Equalizer (3-Band)`：调低/中/高频段。
- `Split Audio Channels` / `Join Audio Channels`：拆合声道。
- `Concatenate Audio`：按时间串接。
- `Merge Audio`：混合多段音频。
- `Empty Audio`：创建静音/空音频。

区分：Concatenate 是前后拼接，Merge 是同时混音。保存前留意削波，多个满音量音轨相加可能失真。

### 音频模型链

`Load Audio Encoder`、`AudioEncoderEncode`、`VAE Encode/Decode Audio`、`Empty Latent Audio` 与 ACE/LTXV/MiniMax Music 专用节点构成音频生成链。采样率和 latent 时长需按模型要求设置。

## 9. 图像检测、几何与抠图

### 常规预处理

- `Detect Edges (Canny)`：输出边缘图，阈值影响线条数量。
- `Apply Morphology`：膨胀、腐蚀、开闭等形态学操作。
- `Remove Background`：加载/运行背景移除模型，通常输出透明图或 mask。
- `Detect Face Landmarks (MediaPipe)`：检测人脸关键点。
- `SDPose Keypoint Extractor` / `Draw Keypoints`：姿态提取与可视化。
- `SAM3 Detect/Track`：提示式分割或视频跟踪。
- `Run Real-Time Detection (RT-DETR)`：目标检测并输出框。

检测节点的置信度和输入尺寸会影响结果。先把检测框、关键点或 mask 可视化，再接生成模型。

### 深度与几何

- `Load/Run Depth Anything 3`：估计深度或几何。
- `Load/Run MoGe`：估计点图、相机视场等几何信息。
- `Convert ... Geometry to Mesh`：把几何预测转换为网格。

单目深度通常是相对深度，不应默认当成真实米制测量。

## 10. 图像后处理与颜色

- `Adjust Brightness` / `Adjust Contrast`：调亮度和对比度。
- `Image RGB to YUV` / `Image YUV to RGB`：颜色空间转换。
- `Normalize Image Colors`：归一化颜色范围/分布。
- `Transfer Color`：把参考图颜色统计转移到目标图。
- `Add Noise to Image`：像素层加噪，不等同于扩散 latent 噪声。
- `GLSL Shader`：执行着色器图像处理，属于高级可编程效果。
- `Draw Text Overlay`：把文字绘制到 IMAGE。

生成式步骤结束后再做颜色处理更容易控制；如果后续还要 VAE 重编码，颜色可能再次变化。

## 11. 3D 节点

### 数据形态

- Mesh：顶点、面、法线、UV、材质。
- Point Cloud：点及其颜色/属性。
- Gaussian Splat：用于新视角渲染的高斯集合。
- Voxel：三维网格体素。

### 常见流程

```text
Load/模型生成 3D
  → Get/Convert Mesh
  → Remesh / Decimate / Smooth / Weld / Fill Holes
  → UV Unwrap / Texture / Bake
  → Preview / Render
  → Save 3D
```

### 高频操作

- `Decimate Mesh`：减少面数，细节与性能折中。
- `Remesh Mesh`：重建更均匀拓扑，可能改变细节。
- `Smooth Mesh Normals`：平滑明暗，不一定改变几何位置。
- `Weld Vertices`：合并接近顶点，阈值过大会破坏结构。
- `Unwrap Mesh UVs`：生成纹理坐标。
- `Bake Normal Map/Ambient Occlusion`：把几何/光照信息烘焙为纹理。
- `Render Mesh/Splat`：从相机视角生成图像。

导出前核对坐标轴、单位、法线方向、UV、贴图路径和目标软件支持格式。

## 12. 文本、逻辑与工具节点

### 文本

`Concatenate Text`、`Format Text`、`Replace Text (Regex)`、`Extract Text`、`Trim Text`、`Text Length`、`Convert Text Case` 等用于动态构造提示词或保存说明。

风险：正则替换可能吞掉内容，JSON 提示必须正确转义，文件路径字符串需注意操作系统差异。

### 逻辑

`If/Else Switch`、`And`、`Or`、`Not` 能根据 BOOLEAN 选择分支。它们让一个工作流支持多个模式，但被选中的输出链才会决定实际执行范围。

### 数字与转换

`Int`、`Float`、`Convert Number`、`Math Expression`、`Curve Editor` 可生成动态参数。传给宽高、帧数、索引时，应确保结果为允许范围内的整数。

### 列表

`Create List`、批次/列表合并、shuffle 和 deduplicate 节点服务于批量媒体。ComfyUI 的 batch tensor、节点列表输出和队列任务是三种不同概念；看到 `OUTPUT_IS_LIST` 语义时优先查看节点文档。

## 13. 训练与数据集节点

当前内置训练类别含 `Make/Load/Save Training Dataset`、`Resolution Bucket`、`Train LoRA`、`Plot Loss Graph` 等。

训练前必须确认：

- 数据许可与隐私。
- 图片/视频和 caption 是否正确配对。
- bucket 分辨率和裁剪策略。
- 基础模型、目标模块和精度。
- 输出路径、检查点间隔、磁盘空间。
- 显存和预计时长。

节点能运行不代表训练配置合理。先用少量数据和短步数验证整个数据/保存链，再开始长训练。

## 14. Deprecated 与 Experimental

### Deprecated（已弃用）

保留它们主要为了打开旧工作流。新建工作流时选择替代节点，避免未来更新后失效。常见例子包括旧 ControlNet Apply、旧 Batch Images、旧图像/文本工具和某些旧保存节点。

### Experimental（实验性）

实验节点的参数、效果和兼容性可能快速变化。使用时：

1. 记录 ComfyUI commit/版本。
2. 保存未使用实验节点的基线工作流。
3. 不把实验结果当作跨设备完全可复现承诺。

## 15. 查模型专用节点的正确顺序

1. 在 [全部内置节点索引](03-全部内置节点索引.md) 搜内部类名，确认输入输出和源码类别。
2. 在 ComfyUI 内打开节点帮助。
3. 从 Templates 加载同模型官方工作流，观察节点上下游。
4. 阅读 ComfyUI 官方对应模型教程和模型卡。
5. 固定模板基线后一次只改一个参数。

如果索引里没有某节点，它很可能来自第三方包、云 API、不同版本或前端扩展，而不是“搜索失灵”。
