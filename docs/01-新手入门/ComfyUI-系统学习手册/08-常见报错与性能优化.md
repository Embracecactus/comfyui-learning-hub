# 08｜常见报错与性能优化

## 1. 排错先保留四类证据

不要只说“不能用”。至少记录：

1. 画布上变红的节点标题和内部类型。
2. 终端/控制台从 `Error occurred` 开始的完整错误与堆栈末尾。
3. ComfyUI 版本、安装方式、GPU 型号和显存。
4. 触发步骤、模型名、分辨率、batch、工作流来源。

先保存失败工作流副本，再做修改。

## 2. 快速定位流程

```text
页面打不开？
├─ 是 → 看启动终端、端口占用、进程是否退出
└─ 否 → 节点变红/执行失败？
        ├─ 加载前就红 → 缺节点、缺模型、输入值不合法
        └─ 执行后报错 → 找第一个失败节点和堆栈末尾
             ├─ OOM → 降像素/batch/模型规模
             ├─ shape/type → 模型或数据不兼容
             ├─ file not found → 路径/文件名/权限
             └─ import/module → 插件依赖或环境错误
```

## 3. CUDA out of memory

按影响和安全性从上到下处理：

1. `batch_size` 改为 1。
2. 降低宽高、视频帧数或音频时长。
3. 关闭其他占 GPU 的程序。
4. 使用 tiled VAE 解码/编码或分块放大。
5. 按模型官方建议使用较低精度/量化权重。
6. 使用适合当前版本的显存参数或模型卸载策略。
7. 换更小模型或更大显存设备。

`--lowvram`、`--novram` 等参数会显著影响速度，而且当前版本的动态显存管理可能改变它们的实际作用。不要把它们当作万能修复；先减少像素和 batch。

## 4. 页面打不开

| 检查 | 方法 |
|---|---|
| 程序是否仍在运行 | 看终端是否退出或有 Traceback |
| 地址是否正确 | 本机通常是 `http://127.0.0.1:8188` |
| 端口是否改过 | 查启动日志中的实际 URL |
| 是否远程访问 | 服务端需要监听可访问地址，云平台还需端口转发/安全组 |
| 端口是否被占用 | 更换 `--port` 或关闭占用程序 |
| 浏览器缓存异常 | 强制刷新；不要先清空整个用户数据目录 |

## 5. 模型下拉框为空

- 模型放错子目录。
- 文件仍在压缩包中。
- 扩展名或文件本身不受该加载器支持。
- Desktop 使用的是另一个数据目录。
- `extra_model_paths.yaml` 配置错误。
- 放入文件后没有按 `r` 刷新或重启。
- 当前节点期待的是 VAE/LoRA/ControlNet，而你放的是 checkpoint。

## 6. Missing Node / 节点未定义

先记下内部类型，不要只记用户改过的标题。可能原因：

- 没安装对应自定义节点包。
- 包已安装但启动时 `IMPORT FAILED`。
- 节点在新版本改名、移动或删除。
- 工作流用了云 API 节点或前端扩展。
- 安装到了另一个 ComfyUI 实例。

优先用 Manager 的缺失节点能力定位来源，再核对工作流作者给的仓库列表。不要为了一个节点安装不明整合包。

## 7. Import failed / No module named

这通常是 Python 环境或第三方节点依赖问题：

1. 确认启动 ComfyUI 使用的 Python 路径。
2. 确认安装依赖时使用同一个 Python。
3. 阅读报错节点仓库要求，不要直接全局升级所有包。
4. 更新节点前记录旧版本；必要时回到作者声明兼容的版本。
5. 将问题节点暂时禁用后验证核心 ComfyUI 是否正常。

不要用系统 `pip` 覆盖 Desktop/Portable 自带环境。

## 8. 类型、shape 和 size mismatch

常见根因：

- LoRA 与基础模型架构不匹配。
- VAE、ControlNet、文本编码器与模型不匹配。
- 图像批次尺寸或通道数不一致。
- 视频帧数不满足模型时序约束。
- 模型专用 latent 被普通 latent 节点错误处理。
- 工作流版本与节点实现不一致。

回到模型官方模板，逐项比较加载器、组件文件和专用 conditioning。不要只尝试改 Resize。

## 9. 黑图、花图、NaN

检查：

- VAE 是否匹配。
- 模型精度是否受当前 GPU 支持。
- 是否强制了不合适的 fp16/fp8 VAE。
- CFG/guidance 是否极端。
- LoRA 总强度是否过高。
- 模型文件是否完整。
- 终端是否出现 `NaN`、overflow 或 dtype 错误。

先回到官方默认模板和默认精度，再逐个恢复修改。

## 10. 运行很慢但没有报错

- 第一次运行正在从磁盘加载模型，通常较慢。
- 模型频繁在 RAM/VRAM 间卸载，速度会下降。
- CPU 模式或 VAE 在 CPU 上运行。
- 分辨率、帧数、steps 或 batch 过高。
- 同时加载多个大模型导致内存压力。
- 预览方法、分块处理和某些插件会增加耗时。

用同一工作流跑第二次，记录“模型加载时间”和“采样时间”分别是多少，才能判断瓶颈。

## 11. 二分法缩小问题

复杂工作流失败时：

1. 复制工作流。
2. 保留最短输出链：模型 → 条件 → 采样 → 解码 → 保存。
3. 确认基础链能跑。
4. 每次恢复一个模块：LoRA、ControlNet、放大、自定义后处理。
5. 哪一步恢复后失败，问题就在该模块及其输入附近。
