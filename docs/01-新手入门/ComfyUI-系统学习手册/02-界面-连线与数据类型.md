# 02｜界面、连线与数据类型

## 1. 界面分区

当前新版界面通常包含：

- 左侧栏：资产、节点、模型、工作流、模板和队列入口。
- 中央画布：摆放节点、分组、注释和连线。
- 顶部：工作流标签、新建工作流、运行和队列控制。
- 底部：控制台、帮助、快捷键、设置和画布导航。
- 节点文档：选中节点后打开帮助/文档，可查看该节点当期说明。

不同前端版本的图标位置可能变化，功能名比图标位置更可靠。

## 2. 节点的组成

一个节点通常包含四部分：

```text
┌─ 节点标题：KSampler ──────────────────┐
│ 输入端口  model          seed  1234   │
│ 输入端口  positive       steps 20     │
│ 输入端口  negative       cfg   7.0    │
│ 输入端口  latent_image   denoise 1.0  │
│                            LATENT 输出 ├──○
└───────────────────────────────────────┘
```

- 左侧圆点通常是输入。
- 右侧圆点通常是输出。
- 节点内部控件是参数；部分控件可转换成输入端口。
- 端口旁的大写字样是数据类型。
- 标题可以重命名，但内部节点类型不会因此改变。

## 3. 连线规则

从上游输出圆点按住鼠标拖到下游输入圆点。通常只有相同或兼容类型才能连接。

错误示例：

- `IMAGE` 不能直接接 `LATENT`，中间需要 `VAE Encode`。
- `LATENT` 不能直接接 `Save Image`，中间需要 `VAE Decode`。
- `CLIP` 不是提示词条件，必须经过 `CLIP Text Encode` 才得到 `CONDITIONING`。
- `MODEL` 不能接到 `vae` 输入；名称相似不代表类型相同。

如果一条线接不上，先看两端的数据类型，不要反复拖拽。

## 4. 最重要的数据类型

| 类型 | 内容 | 典型转换 |
|---|---|---|
| `MODEL` | 扩散/去噪模型 | Checkpoint 或 Diffusion Model 加载器产生 |
| `CLIP` | 文本编码器对象 | 送入 CLIP Text Encode |
| `CONDITIONING` | 编码后的生成条件 | 送入采样器/Guider |
| `VAE` | 编码器与解码器 | `IMAGE ↔ LATENT` |
| `LATENT` | 潜空间张量及附加信息 | 采样器处理的主要对象 |
| `IMAGE` | 像素图像批次 | 保存、预览、裁剪、放大 |
| `MASK` | 0～1 遮罩 | 控制局部重绘或合成区域 |
| `CONTROL_NET` | 已加载的 ControlNet | 与图像条件一起修改 conditioning |
| `CLIP_VISION` | 图像编码器 | 把参考图编码成视觉特征 |
| `AUDIO` / `VIDEO` | 音频或视频数据 | 音视频专用节点处理 |
| `INT` / `FLOAT` / `STRING` / `BOOLEAN` | 数字、文本、开关 | 参数节点或转换节点产生 |

一个容易混淆的点：`IMAGE` 和 `MASK` 在内部可能都是张量，但含义、通道和数值约定不同，不能仅因为“都是图片”就随便互接。

## 5. 添加、搜索和删除节点

- 双击空白画布，输入英文显示名或关键字搜索。
- 也可从左侧 `Nodes` 节点库搜索并拖入画布。
- 选中节点按 `Delete` 或 `Backspace` 删除。
- 不知道节点在哪个菜单时，搜索比逐级翻分类更快。
- 社区教程若使用中文名，建议同时搜索括号中的英文类名。

## 6. 画布常用操作

常见操作会随键位设置略有差异，可从界面快捷键面板确认：

- 鼠标滚轮缩放；拖动画布或按住空格平移。
- 框选或按住修饰键多选节点。
- `Ctrl/Cmd + C`、`Ctrl/Cmd + V` 复制粘贴。
- `Ctrl/Cmd + Z` 撤销。
- `Ctrl/Cmd + S` 保存当前工作流。
- 拖入工作流 `.json` 或带工作流元数据的 PNG 可加载工作流。
- 节点右键菜单可重命名、折叠、禁用/旁路、转换参数为输入。

先在你的版本中打开快捷键面板核对，避免不同前端版本带来的差异。

## 7. Reroute、Primitive、Note、Group

这些节点/画布元素不一定来自后端 Python 注册表，但对整理工作流很重要。

### Reroute（重路由）

只整理连线，不处理数据。它会根据已连接端口继承类型。适合把很长的线沿画布边缘布置，避免穿过节点。

### Primitive（原始值）

把一个参数变成可复用输入，例如一个 seed 同时控制多个节点。连接后会适配 `INT`、`FLOAT`、`STRING` 等类型。

### Note（注释）

记录模型来源、参数理由和操作说明，不参与执行。分享工作流时非常有价值。

### Group（分组）

用彩色框标出“模型加载”“提示词”“采样”“后处理”等区域。分组本身不改变执行顺序。

## 8. ComfyUI 如何决定执行顺序

执行顺序由依赖关系决定，不是按节点从左到右的位置决定。ComfyUI 从输出节点向上游追踪，只执行本次输出需要的节点。

因此：

- 把节点放在最左边不代表它最先运行。
- 没有连接到任何输出链的孤立节点通常不会执行。
- 上游输入和参数未变时，ComfyUI 可以复用缓存，不必重复计算。
- 一个工作流可以有多个 `Save Image` / `Preview Image` 输出分支。

## 9. 队列、历史和取消

- `Run` / `Queue Prompt`：把当前工作流提交到队列。
- Queue：查看正在运行和等待运行的任务。
- History：查看已完成记录并重新加载。
- Interrupt/Cancel：中断当前任务或取消排队任务；显存释放可能需要片刻。

连续点击运行会排入多个任务。小白遇到“怎么还在不停生成”时，先看队列里是否已有多条任务。

## 10. 工作流和 API Prompt 不是同一种 JSON

- 工作流 JSON 保存节点位置、尺寸、连线、分组和控件值，适合在 UI 中编辑。
- API Prompt JSON 只保留执行所需的节点类型和输入，适合程序调用。

导入失败时先确认拿到的是哪一种。不要把 API Prompt 当作普通工作流直接拖入画布。
